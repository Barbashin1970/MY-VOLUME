# ПРИЛОЖЕНИЯ

К отчёту [llm-server-2x-rtx5090-report-2026-11-03.md](llm-server-2x-rtx5090-report-2026-11-03.md).
Номера источников в квадратных скобках — по списку отчёта. Пометки: [И] — из источника, [Р] — расчёт,
[О] — оценка без точного источника.

## ПРИЛОЖЕНИЕ А. Расчёт размещения основной модели

Модель — Qwen3.6-27B в FP8 на двух картах (TP=2). Qwen3.8-27B построена по той же схеме слоёв [9];
число голов внимания у неё не сверялось.

| Величина | Значение | Откуда |
|---|---|---|
| Веса в FP8 | 30,9 ГБ, ≈15,5 ГБ на карту | [И] размер репозитория Qwen3.6-27B-FP8 [6] |
| Слои | 64: 16 полного внимания, 48 линейных (Gated DeltaNet) | [И] config.json [8] |
| Кэш на токен контекста | 16 слоёв × 2 (K и V) × 4 головы × 256 × 2 байта = 65 536 байт = 64 КБ | [Р] по [8] |
| Память линейных слоёв | 48 слоёв × 48 голов × 128 × 128 ≈ 37,7 млн чисел — ≈75 МБ на разговор в BF16 | [Р] по [8]; формат хранения зависит от движка |
| Доступно vLLM | 90 % от 32 ГБ = 28,8 ГБ на карту | [И] значение `--gpu-memory-utilization` по умолчанию (`vllm serve --help`) |
| Буферы вычислений | ≈2 ГБ на карту | [О] |
| Остаток на кэш | 28,8 − 15,5 − 2 ≈ 11 ГБ на карту, ≈22 ГБ на двух | [Р] |
| Ёмкость кэша | 22 ГБ ÷ 64 КБ ≈ 335 тыс. токенов; за вычетом памяти линейных слоёв — 250–300 тыс. | [Р] |
| В разговорах | ≈30 по 8 тыс. токенов (240 тыс.) или ≈8 по 32 тыс. (256 тыс.); с кэшем в FP8 — примерно вдвое больше | [Р] |
| Потолок скорости на одного | 1792 ГБ/с ÷ 15,5 ГБ ≈ 115 токенов/с: на каждый токен карта читает свою половину весов | [Р]; пропускная способность — [10] |

Откуда разброс 250–300 тыс.: при 30 разговорах память линейных слоёв занимает 30 × 75 МБ ≈ 2,3 ГБ в
BF16 (остаётся ≈300 тыс. токенов) или вдвое больше, если движок хранит её в FP32 (≈265 тыс.) [Р].

Как проверить: vLLM печатает фактическую ёмкость при запуске строкой `GPU KV cache size: … tokens`
(П3), скорость меряет `vllm bench serve` (П4).

## ПРИЛОЖЕНИЕ Б. Программа проверки после сборки

Каждый замер — серией из трёх прогонов. Перед серией записать версии драйвера, CUDA, vLLM и модели,
параметры запуска vLLM и ограничение мощности карт.

| № | Что | Как | Критерий |
|---|---|---|---|
| П1 | потребление | `nvidia-smi --query-gpu=power.draw --format=csv -l 1` во время П4 | пик карт + 253 Вт процессора ≤ 80 % мощности блока; если выше — ограничить мощность карт и повторить П4 |
| П2 | линии PCIe | `nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.width.current --format=csv` под нагрузкой: в простое линия замедляется | у обеих карт 5 и 8 |
| П3 | ёмкость кэша | строка `GPU KV cache size` в журнале vLLM | сверить с приложением А: 250–300 тыс. токенов |
| П4 | скорость | `vllm bench serve` для 1 и 30 одновременных пользователей | записать; сравнить с потолком 115 токенов/с |
| П5 | устойчивость | час непрерывной нагрузки | без сбоев и перезапусков |
| П6 | нагрев | `nvidia-smi --query-gpu=temperature.gpu,clocks.sm --format=csv -l 5` во время П5 | частоты к концу часа не падают |
| П7 | частота памяти | `sudo dmidecode -t memory \| grep "Configured Memory Speed"` | записать |
| П8 | русский язык | методика ниже | выбрана основная модель |

Методика П8 — сравнение моделей на русском:

1. 50 вопросов из реальных задач НГУ — учебных, административных, по документам — с эталонными
   ответами, составленными до прогона.
2. Каждая модель отвечает на все вопросы при одинаковых настройках: temperature 0, одна длина контекста.
3. Ответы оцениваются вслепую: оценщик не знает, какая модель отвечала.
4. Побеждает модель с наибольшим числом верных ответов; при равенстве — более быстрая по П4.
5. Кандидаты: Qwen3.8-27B, Qwen3.6-27B, T-pro-it-2.1; GigaChat3.1-10B-A1.8B — как лёгкий вариант.

## ПРИЛОЖЕНИЕ В. Подключение проекта: РАГРАФ

РАГРАФ обращается к модели через OpenAI-совместимый клиент, поэтому к серверу подключается правкой
`.env`, без правки кода:

```env
LLM_ENABLED=true
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://<сервер>/v1
OPENAI_API_KEY=<ключ из LiteLLM>
LLM_MODEL=<имя основной модели на сервере>
EMBEDDINGS_ENABLED=true
EMBED_MODEL=<имя модели эмбеддингов на сервере>
```

- Значение `openai` допустимо: `~/RAGRAF/backend/app/config.py:46`.
- Если эмбеддинги отдаёт отдельный адрес, его задают `EMBEDDING_BASE_URL` и `EMBEDDING_API_KEY`
  (поля `embedding_base_url`, `embedding_api_key`: `~/RAGRAF/backend/app/config.py:38–39`).
- Для провайдера не-Ollama предел длины ответа поднимается с 4000 до 16000 токенов:
  `~/RAGRAF/backend/app/api/sandbox.py:262`.
- В выпадающем списке рядом с моделью сервера останутся пресеты gpt-4o
  (`~/RAGRAF/backend/app/api/sandbox.py:476–484`) — на работу не влияет.
