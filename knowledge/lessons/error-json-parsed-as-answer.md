# Урок: отказ соседней системы разобран как её ответ

## Что произошло

На странице администратора АРХИ появилась строка:

> Слепка в поставке нет: каталог **undefined** пуст либо опись не читается.

Изделие утверждало о данных то, чего не проверяло. Сервер был поднят сборкой,
в которой точки `/api/slepok` ещё не было; она ответила `404` с телом
`{"detail":"Not Found"}`.

Код выглядел так:

```js
try {
  d = await (await fetch("/api/slepok")).json();   // не упало: JSON валидный
} catch (e) { /* сюда не зашли */ }
if (!d.est) {                                      // undefined → falsy
  pokazat("Слепка нет: каталог " + d.katalog);     // тоже undefined
}
```

## Почему это случилось

**Отказ приходит в том же формате, что и ответ.** FastAPI, как и почти всякий
каркас, отдаёт ошибку структурированным JSON. Значит:

- `response.json()` **не бросает** — обрабатывать нечего;
- `try/catch` ловит только обрыв сети, а не отказ сервера;
- дальше чужой объект читается как свой, отсутствующие поля дают `undefined`,
  и `!d.est` уводит в ветку «данных нет» — то есть отказ превращается
  в утверждение о предметной области.

Отдельная половина урока: **версия своей же соседней сборки — это тоже
окружение.** Страница живёт в браузере неделями, а сервер перезапускают.
Случай «страница новее сервера» не гипотетический, а бытовой.

## Как починили

Код ответа сверяется **до** разбора тела, и диагноз называется словами:

```js
var otvet = await fetch("/api/slepok", { cache: "no-store" });
if (!otvet.ok) {
  pokazat("Опись слепка не отдана: код " + otvet.status
        + ". Если 404 — изделие поднято сборкой, в которой этой точки ещё "
        + "нет: погасите его и запустите заново.");
  return;
}
var d = await otvet.json();
```

Сторож смотрит на **порядок**, а не на наличие: `otvet.ok` обязан стоять
раньше `.json()` — `ARCHI-NSU/tests/test_stranica_administratora.py`.

## Чтобы не повторилось

- **`try/catch` вокруг `fetch` — не обработка ошибок HTTP.** `fetch` отвергает
  обещание только при сетевом обрыве; 404 и 500 для него успех. Проверять
  `response.ok` обязательно и **до** разбора тела.
- Сообщение об отказе называет **код и вероятную причину**, а не пересказывает
  отсутствие данных. «Каталог undefined» и «каталог пуст» чинятся по-разному,
  а выглядят одинаково.
- Где ещё ждать того же: gRPC-статусы, ответы очередей, любые обёртки вида
  `{ok: false, error: …}` — там разбор тем более не падает.
- В наборе проверок это класс «„не упало“ вместо „отклонено“»: утверждать
  надо об отказе с конкретным кодом.
