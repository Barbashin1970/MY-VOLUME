# Теория функциональных систем (Анохин)

Психофизиологическая теория П.К. Анохина (1898-1974), описывающая
**6 стадий целенаправленной деятельности**. В РАГРАФ используется как
основа для жизненного цикла каждой задачи: от события до подкрепления
методолога.

## 6 стадий

| # | Стадия | В терминах системы |
|---|--------|-------------------|
| 1 | **Афферентный синтез** | Сбор события + контекста + памяти прошлых попыток |
| 2 | **Принятие решения** | Выбор сценария реагирования (flow / branching) |
| 3 | **Акцептор результата** | Модель ожидаемого исхода (что значит «получилось») |
| 4 | **Исполнение** | Команды и действия исполнителям (людям / системам) |
| 5 | **Оценка результата** | Сравнение факта с акцептором |
| 6 | **Подкрепление** | Обратная связь системе/методологу — что сработало |

## Применение

Если строишь систему исполнения регламентов / реагирования на
события — проверь, что каждая стадия **материализована**. В РАГРАФ:

- §1 — `etl_snapshots` (нормализованные события) + sensor schema
- §2 — Rule DSL → `flow_executor` (compare/switch real-eval)
- §3 — `Regulation.expected_result.description` (текстовая модель)
- §4 — output-ноды: `leyka_create_task`, webhook
- §5 — синхронная проверка + `acceptance_resolver` (sensor_returned_normal, task_closed_within_sla)
- §6 — `regulation_metrics` + UI бадж + 30-day sparkline

## Особенность Стадии 5

Это **самая сложная** стадия. У РАГРАФ:
- **Синхронная половина** — для критериев типа `no_violation` /
  `specific_output` / `custom`, проверяется в момент прогона.
- **Гибридная половина** — для критериев типа `sensor_returned_normal`
  / `task_closed_within_sla`, требует отложенной проверки через
  `acceptance_resolver` с TTL 24ч.
