# STROY — ИИ-помощник по технике безопасности (Text-to-SQL Demo)

> **Где код:** `~/STROY/`
> **Что это:** интерактивный веб-прототип на **Streamlit** для демонстрации
> семантического поиска + подхода **Text-to-SQL** в сфере охраны труда
> и промбезопасности. Категория D — демо для рассылки клиентам.

## Зачем

Показать заказчику, что можно генерировать **точные** чек-листы СИЗ,
тесты ТБ, аварийные карточки и комплаенс-матрицы **без галлюцинаций**
(без LLM в контуре принятия решений) — на базе структурированной
графовой онтологии.

## 5 ключевых сценариев

1. **🧱 Плановый наряд (строительство)** — выбор вида работ + роль → чек-лист СИЗ, опасные факторы, предписания, запреты.
2. **🧪 Тест по знанию ТБ** — авто-генерация тестов на внимательность перед допуском на объект.
3. **🚨 Аварийные работы ЖКХ** — экстренная карточка действий (прорыв труб, загазованность, затопление).
4. **🏠 Плановые / заявочные работы ЖКХ** — чек-листы для рутинных задач с инструктажами.
5. **📑 Матрица комплаенса** — для ПТО: тип объекта × этап ЖЦ (проектирование → снос) → применимое законодательство (883н, 384-ФЗ, 116-ФЗ) + глобальные риски.

## Архитектура

**Детерминированно, без нейросетей-генераторов.** Данные —
**RDF-подобные триплеты** `[Субъект] → [Предикат] → [Объект]`.

Алгоритмический фильтр в будущем заменяется на реальный `text-to-SQL`
движок поверх реляционной базы (Postgres, DuckDB).

## Главные ценности STROY для других проектов

1. **Streamlit как 248K-демо для коммерческой воронки.** Эталон «1 файл
   `app.py` + RDF-данные → веб-приложение за день». Переносим под любой
   домен с нормативкой.

2. **Text-to-SQL без LLM в контуре принятия решений.** Паттерн «LLM
   только для NL → структурный запрос», а **сама генерация ответа
   детерминирована** через SQL/SPARQL. Антипод «свободному LLM-агенту».

3. **Матрица комплаенса как UI-паттерн** — таблица (тип объекта × этап ЖЦ)
   → ячейка = применимая нормативка. Применимо везде, где есть
   стандарты по жизненному циклу.
