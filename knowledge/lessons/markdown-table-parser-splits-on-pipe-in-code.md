# Урок: «на GitHub таблица целая, на своей странице — обрезана»

> Контекст: РАГРАФ показывает комплект ГОСТ 19, книги и курсы на своей странице
> документации, а Markdown там разбирает собственный код
> `backend/app/services/docs_markup.py`. Авторы — человек и агенты — пишут
> документы «под GitHub».

## Что произошло

31.10.2026, при сверке курса РАГРАФ-V1 с изделием: в таблице курса была ячейка
с операторами языка — «логика `&& || !`». На странице изделия строка таблицы
обрывалась на «логика `&&»: остаток ячейки уехал в следующие столбцы, а столбцы
сверх шапки разборщик отбросил без ошибки. GitHub ту же таблицу показывал верно.

## Почему это случилось

Разборщик делит строку по каждой черте:

```python
def yacheyki(stroka: str) -> list[str]:
    golaya = stroka.strip().strip("|")
    return [ya.strip() for ya in golaya.split("|")]
```

(`backend/app/services/docs_markup.py:246–248`). По правилам GFM черта внутри
обратных кавычек и экранированная `\|` остаются частью ячейки — самописный
разборщик этого не знает.

Глубже: **у одного текста два правила разметки.** Пишут под GitHub, показывают
и печатают своим кодом. Пока таблицы простые, правила совпадают, и разница
не видна, — до первой ячейки с кодом.

## Как починили

- Текст курса переписан без черты в ячейке.
- В заданиях агентам, которые правят документы и книги РАГРАФ, записано: «в ячейках
  таблиц Markdown не ставить символ «|» внутри текста — разборщик страницы режет
  строку по нему».
- Сам разборщик не исправлен: запись в `docs/BACKLOG.md` РАГРАФ, раздел «Сверка курса
  РАГРАФ-V1 с пособием и изделием» (31.10.2026), п. 9.

Пока не починено.

## Чтобы не повторилось

- **Свой разборщик Markdown — значит своё правило разметки, и его надо назвать.**
  Либо разборщик следует GFM (черта в коде и `\|` — часть ячейки), либо его
  ограничение записано в правилах для авторов и сторожится.
- **Сторож на число ячеек.** Каждая строка таблицы делится на столько же ячеек,
  сколько шапка; расхождение — красная проверка, а не молчаливое отбрасывание
  лишних столбцов. Такой сторож ловит черту в ячейке, даже пока разборщик
  не починен.
- **Таблицу из данных собирает скрипт — он и отвечает за черту.** Значения ячеек
  проходят экранирование (если разборщик его понимает) или проверку «черты нет»
  (пока не понимает). Это касается и сборщиков документов: ПМИ РАГРАФ-ФРЕЙМ-51
  07.11.2026 собиралась скриптом из таблиц — правило передаётся ему явно.
- **Тот же класс — «пишем для одного читателя, показывает другой»:** GitHub и своя
  страница, браузер и PDF, редактор и печать. Проверять надо тем средством,
  которым показывают.

## Чем обнаружено

Сверкой курса с изделием (31.10.2026): проверяющий открыл ячейку на странице
изделия и увидел обрыв. Ни один сторож её не нашёл: число ячеек никто не сверял.
