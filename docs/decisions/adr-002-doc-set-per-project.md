# ADR-002: Дефолтный комплект документации на проект

## Контекст

В разных проектах документация писалась по-разному. LEYKA — полный
комплект ГОСТ-19 (5 файлов) + STARTING-A-PROJECT.md + 12 SKILL-файлов
+ AUDIT-REPORT. RAGRAF — ещё полнее: TZ + ARC + UserManual + Strategy +
Economics + Glossary + SKILL-GOST-19. AI-SKLAD — лёгкая версия: IDEA +
STARTING-A-PROJECT + README + 2 SKILL.

Без явного решения каждый раз заново выбираешь, что писать. Это
приводит к **пропуску критичных документов** (нет позиционирования →
не понятно кому продавать; нет ТЗ → не понятно когда «готово»).

## Решение

**Каждый проект пишет комплект документов согласно своей категории.**

### Категория A — заказной коммерческий / грантовый

Полный комплект — 9 документов по 9 стадиям ЖЦ
([00-product-lifecycle](../playbooks/00-product-lifecycle.md)):

| Стадия | Документ | Обязательность |
|--------|----------|----------------|
| 1 | `IDEA.md` | ✅ |
| 2 | `STRATEGY-POSITIONING.md` | ✅ |
| 3 | `ECONOMICS-MARKETING.md` или `NIR-REPORT.md` | ✅ |
| 4 | `TZ_<PROJECT>_GOST19.md` (19.201-78) | ✅ |
| 5 | `ARC.md` (18 секций) | ✅ |
| 6 | `SKILL-NN-*.md` серия (5-15 файлов) | ✅ |
| 7 | `<PROJECT>_UserManual_GOST19.md` + `_AdminGuide_` + `_InstallManual_` + `_PMI_` (4 файла) | ✅ при заказчике / реестре |
| 8 | `README.md` + `README-en.md` | ✅ |
| 9 | `CHARTER.md` (Устав) + `ANNUAL-REPORT.md` (Отчёт) | ✅ при гос/корп отчётности |

**Эталон:** LEYKA (12+ доков), RAGRAF (15+ доков).

### Категория B — pet / learning / внутренний инструмент

Облегчённый комплект — 4 документа:

| Стадия | Документ |
|--------|----------|
| 1 | `IDEA.md` (упрощённый, 6 вопросов) |
| 5 | `ARC.md` (8-12 секций, на одну страницу) |
| 6 | `SKILL-NN-*.md` серия (3-6 файлов) |
| 8 | `README.md` |

**Эталоны:** GONKA / KNIFFEL / SOFIA — 9 SKILL + ARC + CLAUDE + README.

### Категория C — научно-инструментальный (POLINOM-style)

| Стадия | Документ |
|--------|----------|
| 2 | `README.md` с теоретическим обоснованием |
| 3 | `MTS-DOGFOOD-REPORT.md` или эквивалент эмпирической валидации |
| 6 | `SKILL-AGENT-RULES.md` (если есть AI-плагины) |
| 8 | `README.md` + `README-en.md` (билингвальный) |
| доп | `BENCHMARK.md`, `bench results` (live) |

### Категория D — демо для клиента (AI-SKLAD-style)

| Стадия | Документ |
|--------|----------|
| 1 | `IDEA.md` (6 вопросов от ТЗ заказчика) |
| ⨯ | `STARTING-A-PROJECT.md` (эталон стека / архитектуры, общий) |
| 6 | `SKILL-AI-PLAYBOOK.md` + 1-2 SKILL-feature |
| 8 | `README.md` |
| доп | `glossary.md` (для заказчика и команды) |

## Как выбрать категорию

```
Есть заказчик / грант с отчётностью?
├── Да → Категория A
└── Нет
    │
    ├── Это твой research-инструмент (POLINOM)? → C
    │
    ├── Это демо для рассылки клиентам? → D
    │
    └── Иначе → B
```

## Альтернативы

| Вариант | Почему не выбрали |
|---------|-------------------|
| «Один README, остальное по ходу» | Пропускаются критичные стадии. RAGRAF дошёл до 15+ доков только после многих неприятностей |
| «Документация по запросу заказчика» | Не работает: к моменту запроса уже поздно |
| «Шаблоны ГОСТ-19 для всех» | Overhead для pet-проектов; убивает энтузиазм |

## Последствия

### Позитивные
- Чёткий чеклист, что должно быть. AI-ассистент сразу видит пробелы.
- Документация **становится** в порядке прохождения стадий, не «всё сразу».
- При запросе заказчика / грантодателя — комплект уже готов или
  частично готов.

### Негативные
- Категория A — тяжёлая, без AI-ассистента писать 15 документов нереально.
- Можно «переоформить» pet-проект — не стоит.

### Нейтральные
- Категория переключается по ходу: pet → коммерческий = добавляем
  недостающие документы.
