# Критерии необходимости ИИ в продукте

**Не все проекты должны содержать ИИ.** Перед тем как закладывать ИИ-фичу, честно ответь:
нужен ли ИИ **ВНУТРИ** финального продукта — или задача решается классическими методами, а ИИ
полезен лишь на этапе исследования и разработки.

> **Главный принцип.** Многие отличные ИТ-решения **создаются С ПОМОЩЬЮ ИИ** (вайб-кодинг),
> но работают на классических технологиях. Путать «с помощью ИИ» и «с ИИ внутри» — корневая ошибка.

## «С помощью ИИ» vs «С ИИ внутри»

| | Создано **С ПОМОЩЬЮ** ИИ | Содержит ИИ **ВНУТРИ** |
|---|---|---|
| Что это | ChatGPT/Copilot/Cursor написали код | В проде работают ML-модели, LLM-вызовы, embeddings |
| Финал | Классическое приложение | ИИ — часть рантайма |
| Пример | Калькулятор смет (считает по формулам) | Интеллектуальный поиск по регламентам |

## Когда ИИ нужен в продукте

- Неструктурированные данные (тексты, изображения, видео).
- Обучение на больших данных; предсказательная аналитика.
- Распознавание паттернов, которые трудно формализовать правилами.
- Генеративные задачи; персонализация по поведению.

## Когда достаточно классики

- Чёткие правила и детерминированные вычисления.
- CRUD, фильтрация, сортировка, агрегация структурированных данных.
- Калькуляторы по формулам.

## Протокол честной оценки (5 вопросов)

1. Решается ли задача классическими методами (БД, правила, алгоритмы, компьютерное зрение)?
2. Если да — в чём измеримое преимущество ИИ? Оправдана ли доп. сложность?
3. Если нет — какие конкретно подзадачи ТРЕБУЮТ ИИ/ML?
4. Раздели: что **создать** с помощью ИИ, а что должно **содержать** ИИ в финале?
5. Вердикт по каждому компоненту: ИИ внутри — ДА/НЕТ + обоснование.

## Пример

| Задача | Вердикт |
|---|---|
| Парсинг документов | С помощью ИИ один раз → дальше обычная БД |
| Интеллектуальный поиск по регламентам | ДА, embedding search |
| Калькулятор стоимости по параметрам | НЕТ, формулы и правила |
| Распознавание размеров на чертежах | НЕТ для LLM → специализированное компьютерное зрение |

## Не путать с

- [preconstruction](preconstruction.md) — фаза, на которой ИИ помогает **исследовать**
  идею; здесь — отдельный вопрос про ИИ **внутри** рантайма продукта.
- [anti-scope](anti-scope.md) — родственный приём «честно решить, чего НЕ делаем»; антископ
  про функции, эти критерии — про технологию.
