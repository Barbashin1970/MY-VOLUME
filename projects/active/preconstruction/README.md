# PRECONSTRUCTION

> **Где код:** `~/PRECONSTRUCTION/` (не git-репозиторий — папка-методология + скиллы)
> **Что это:** база знаний + два зеркальных Claude Code скилла (`preconstruction-ru` /
> `preconstruction-en`). На вход — сырая проектная идея; на выход — пресейл-отчёт с
> питчем и вердиктом «нужен ли ИИ ВНУТРИ продукта».
> **Категория B** — внутренний инструмент/методология (скилл), не клиентский продукт.

## Зачем

ИИ на стадии **preconstruction / presale** — ДО начала реализации, где решается 70–80%
успеха проекта и предотвращается 30–40% перерасхода. Центральный принцип: ИИ — инструмент
**исследования и упаковки идеи**, а не обязательный компонент продукта. Жёстко разделяем
«создано **С ПОМОЩЬЮ** ИИ» (вайб-кодинг) ≠ «содержит ИИ **ВНУТРИ**» (ML в проде). Собрано из
трёх материалов НГУ/НГАУДИ (мини-хакатон для архитекторов-градостроителей).

## Что внутри (What)

- **`knowledge-base/`** — русская база знаний: 8 атомарных заметок (01–08) + индекс +
  `sources/` (три исходных материала, конвертированных в MD).
- **`knowledge-base-en/`** — зеркальная английская база для иностранных студентов (та же структура).
- **`.claude/skills/preconstruction-ru/`** и **`preconstruction-en/`** — зеркальные скиллы;
  каждый = `SKILL.md` + `references/` из 4 файлов (interview-protocol, research-roles,
  audit-checklist, report-template).
- **`README.md`** — билингвальная точка входа.

## Пять этапов пресейла (ядро)

| # | Этап | Суть |
|---|------|------|
| 1 | Идентификация проблемы | кто страдает, масштаб, потери |
| 2 | Бизнес-анализ | рынок, конкуренты, SWOT, TAM/SAM/SOM |
| 3 | Техэкспертиза | стек, нормативы (СП/ГОСТ/ФЗ), риски |
| 4 | **Применимость ИИ** (ключевой) | нужен ли ИИ ВНУТРИ продукта |
| 5 | Упаковка в питч | презентация + вердикт по ИИ |

Центральный вердикт всей методологии — этап 4: «нужен ли ИИ ВНУТРИ: ДА/НЕТ» с обоснованием.

## Механика скилла

Скилл = диалог → многопоточное исследование → аудит → сведение:

- **Фаза 0 — диалог/скоупинг:** Restate + 2–3 волны `AskUserQuestion`, выбор глубины
  «быстрая»/«полная», антископ, нормативный контекст РФ.
- **Фаза 1 — параллельные потоки-агенты** (в одном сообщении): A Бизнес-аналитик (этапы 1–2),
  B Маркетолог (этап 2), C Системный аналитик ИИ · техэкспертиза (этап 3), D Системный
  аналитик ИИ · применимость ИИ (этап 4).
- **Фаза 2 — адверсариальный аудит:** проверка чисел/источников, противоречий между потоками,
  пробелов, перепроверка вердикта по ИИ (в «полной» глубине — 2 независимых аудитора).
- **Фаза 3 — сведение** в единый `research/<слаг>-YYYY-MM-DD.md` (executive summary, разбор по
  5 этапам, раздел «Применимость ИИ», питч Problem-Solution-Market-Tech-Team + roadmap, риски,
  журнал аудита).

## Load-bearing инсайты методологии

- **Честность важнее «крутости ИИ»** — признать, что классика лучше, ценится выше всего.
- **«Двойной пресейл»** для ИТ-для-стройки: уровень 1 — строительная проблема, уровень 2 — ИТ-решение.
- Параллельные `Agent`-вызовы — в **одном** сообщении, иначе нет реальной параллельности.
- **Пределы LLM** (кейс с чертежами фасадов): ChatGPT «выдумывает» размеры → для точной
  техработы нужны специализированные платформы (KREO, Togal.AI, Bluebeam Revu), не LLM «в лоб».
- **«Строитель с ИИ» ≠ ML-инженер**: пользователь готовых инструментов, +25–40% к зарплате.

## Как использовать для исследований

1. **По назначению** — открыть `~/PRECONSTRUCTION` в Claude Code, вызвать `/preconstruction-ru`
   (или `/preconstruction-en` по языку отчёта): «проработай идею: <описание>».
2. **База знаний как учебник** — читать `knowledge-base/` (или `-en`) по порядку 01 → 02 → … → 08.
3. **Переносимый приём** — родственен [discovery-interview](../../../knowledge/skills/discovery-interview.md)
   и операционализирует **стадию 2** (поиск ниши и позиционирование).
