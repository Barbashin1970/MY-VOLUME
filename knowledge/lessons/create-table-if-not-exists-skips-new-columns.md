# Урок: «опрос ушёл, ответ пропал»

> Контекст: РАГРАФ, контур обратной связи. Вердикт регламента уходит в Telegram
> с вопросом и кнопками «Да / Нет»; опрос записывается в таблицу `feedback_opros`
> (DuckDB, `live_etl.duckdb`), ответ — в `feedback_otvet` и становится величиной
> для регламента. Таблицы создаёт `backend/app/services/feedback_store.py`
> оператором `CREATE TABLE IF NOT EXISTS` при старте.

## Что произошло

С 09 по 27.10.2026 — восемнадцать дней — действующий экземпляр не записал ни
одного опроса. Сообщения уходили, журнал доставок писал «отправлено, ошибки нет»,
а человек, нажав кнопку, видел «Этот вопрос больше не действует — ответ
не записан». На дашборде кампуса ответов не было. Нажатия 27.10 утрачены
безвозвратно.

## Почему это случилось

- 08.10 (`9111790`) таблицу `feedback_opros` на томе прода создала первая версия.
- 09.10 (`4da7d7c`) в текст `CREATE TABLE IF NOT EXISTS feedback_opros (…)` добавили
  колонку `tekst`. **Для существующей таблицы этот оператор не делает ничего** —
  ни ошибки, ни новой колонки.
- Запись опроса с новой колонкой падала; ошибку ловил `try/except` и превращал
  в предупреждение в журнале процесса. Доставка к этому моменту уже состоялась
  и отчиталась успехом.
- **Проверки каждый раз создают базу заново**, сразу с новой схемой. Таблицы
  от прежней версии в наборе не было ни разу.

## Как починили

Коммит `5188893` от 27.10.2026, разбор — `docs/OBRATNAYA-SVYAZ-RAZBOR.md`, § 9.

1. **Сверка колонок при старте.** Перечень `_DOBAVLENNYE_KOLONKI` в `feedback_store.py`:
   для каждой колонки, добавленной после первого выпуска, при подготовке базы
   читается `PRAGMA table_info('<таблица>')`, и недостающая добавляется через
   `ALTER TABLE … ADD COLUMN`.
2. **Сбой записи виден там, где смотрят результат.** `zapisat_opros` возвращает
   текст ошибки, и журнал доставок пишет «опрос не записан: …» вместо молчаливого
   успеха.
3. **Проверка начинает со старого тома:**
   `test_tablica_oprosov_prezhney_versii_poluchaet_kolonku` создаёт таблицу в схеме
   от 08.10 и запускает новый код поверх. Её видели красной до правки. Вторая —
   `test_sboy_zapisi_oprosa_viden_v_zhurnale_dostavok`.

## Чем обнаружено

Жалобой человека: «я жму да и нет — уже есть в системе, но нет на дашборде
кампуса». Ни проверки, ни журналы сбоя не показали.

## Чтобы не повторилось

- **`IF NOT EXISTS` — это «создать один раз», а не миграция.** Любое изменение
  колонок после первого выпуска — явный шаг миграции (`ALTER TABLE … ADD COLUMN`)
  или сверка объявленного состава с `PRAGMA table_info` при старте.
- **В наборе проверок есть случай «система уже работала до выкладки»:**
  таблица в схеме прежней версии, поверх — новый код.
- **Сбой записи, от которой зависит человек, виден в журнале результата,**
  а не только предупреждением в журнале процесса.
- **«Сообщение ушло» ≠ «контур работает».** Канал обратной связи проверяют
  по «ответ записан», а не по «отправлено».
