# Урок: «браузерный автоперевод ломает React-DOM»

## Что произошло

В вебе SOFIA (React Native Web, PWA) пользователь периодически видел сломанный
интерфейс: кнопка «Создать рецепт» превращалась в обрывок «рел комп», флаг языка
показывал EN, а текст был на русском, надписи перемешивались. Баг «плавал» —
проявлялся не всегда. У пользователя были установлены **расширение-переводчик и
VPN**, и «приходилось что-то отключать, чтобы починить».

## Почему это случилось

Не баг вёрстки и не баг VPN. Конфликт **React ↔ браузерный переводчик**
(Google Translate, встроенный перевод Chrome/Safari, Яндекс, расширения):

1. React (и RN Web) держит собственный виртуальный DOM и ожидает, что текстовые
   узлы остались такими, какими он их создал.
2. Переводчик **мутирует реальный DOM в обход React**: оборачивает каждый
   текстовый узел в `<font>`-теги и подменяет содержимое на перевод.
3. На следующем ре-рендере (смена темы/языка, фокус инпута, перерисовка) React
   ищет свои старые узлы — их уже подменили. Реконсиляция ломается, текст
   застывает обрывками перевода. Классический симптом — также краш
   `Failed to execute 'removeChild' on 'Node'`.

**Триггер автоперевода** — расхождение «язык страницы ≠ целевой язык браузера».
В проде был жёстко зашит `<html lang="en">`, а контент рендерился на русском.
**VPN менял геолокацию → менялась целевая локаль браузера → автоперевод то
включался, то нет.** Отсюда «плавающий» характер.

## Как починили

Приложение уже имеет **собственную i18n на 4 языка**, поэтому браузерный
автоперевод бесполезен и только вредит. Решение — полностью его отключить,
тремя слоями + синхронизация языка:

1. `<html translate="no" class="notranslate">` + `<meta name="google" content="notranslate">`.
2. Те же атрибуты на `<html>` и на корневом контейнере `#root` (Safari/Яндекс/
   расширения уважают `translate="no"` именно на узле).
3. Синхронизация `document.documentElement.lang` с активным языком i18n при
   каждой смене языка — убирает сам триггер автоперевода (+ польза для a11y/SEO).

Тонкость для Expo/RN Web со статическим экспортом: **`+html.tsx` игнорируется
при static export**, поэтому в проде гарды надо инжектить в рантайме (через JS,
рядом с остальными PWA-тегами), а не только декларативно в `+html.tsx`.

Файлы в SOFIA: `expo/app/+html.tsx`, `expo/app/_layout.tsx`,
`expo/locales/index.ts`; бамп `CACHE_NAME` в `service-worker.js`, чтобы фикс
долетел до установленных PWA.

## Чтобы не повторилось

**Правило для любого веб-проекта с собственной i18n:** браузерный автоперевод —
чистый вред, отключай его сразу.

- На старте веб-проекта с i18n добавляй `translate="no"` + `notranslate` на
  `<html>`/`#root` и `<meta name="google" content="notranslate">`.
- Держи `<html lang>` синхронным с активным языком приложения — иначе браузер
  будет предлагать перевод и ломать DOM.
- При жалобе «UI иногда показывает кашу из текста / надписи обрезаны / краш
  removeChild» — **первым делом** спроси про переводчик/расширения, не ищи баг
  в вёрстке.
- Для статических экспортов (Expo RN Web, Next export и т.п.) помни: декларация
  в шаблоне HTML может игнорироваться — дублируй защиту рантайм-инъекцией.
