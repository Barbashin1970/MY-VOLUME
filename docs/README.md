# docs/

Это **публичная (или полу-публичная) часть** vault'а. Сюда попадает только
то, что готово к чужим глазам: коллег, заказчиков, читателей GitHub Pages.

> **Чем `docs/` отличается от `knowledge/`:**
> - `knowledge/` — твой рабочий черновик; пишешь для себя.
> - `docs/` — финальный документ; пишешь для других.
>
> Один и тот же материал может пройти путь `inbox → knowledge → docs`.

## Структура

| Подпапка | Что внутри | Стиль |
|----------|-----------|-------|
| [architecture/](architecture/) | Архитектурные обзоры систем | Длинные, с диаграммами |
| [decisions/](decisions/) | ADR — Architecture Decision Records | Короткие, неизменяемые |
| [playbooks/](playbooks/) | Step-by-step руководства | Императивные шаги |

---

## Правила, не нарушаемые в docs/

1. **Никаких `[[wikilinks]]`.** Только `[Текст](relative/path.md)`. Wikilinks
   не рендерятся в GitHub Pages.
2. **Никаких `TODO:`, `FIXME:`, «допишу позже».** Публикуется только готовое.
3. **Frontmatter обязателен.** Это документ, не заметка — нужны `title`,
   `description`, `status`, `updated`.
4. **Картинки — относительными путями** к `../assets/`.
5. **Не дублируй `knowledge/`** — ссылайся.

---

## Когда документ переезжает сюда

- Когда коллега сказал «дай ссылку, что почитать про X».
- Когда черновик в `knowledge/` стал достаточно полным, что его не стыдно
  показать.
- Когда решение из `projects/<x>/decisions.md` стало общим правилом — ADR
  в `decisions/`.

---

## Публикация через GitHub Pages

Минимальный `_config.yml` в корне vault'а:

```yaml
title: Граф знаний Олега
theme: just-the-docs
exclude:
  - inbox/
  - templates/
  - assets/
  - projects/active/    # если проектные карточки приватные
  - people/
  - meetings/
```

Тогда наружу пойдёт только `docs/`, `knowledge/` (если не исключишь) и
`concepts/`. `projects/`, `people/`, `meetings/` остаются приватными.
