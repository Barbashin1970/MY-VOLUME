# Стадия 2 — Поиск ниши и позиционирование

**Вход:** IDEA.md закрыта.
**Выход:** `STRATEGY-POSITIONING.md` (если проект коммерческий или для гранта).
**Время:** 1-2 недели, если делать на основе внешних источников
(научные статьи, конкурентные обзоры).
**Эталон:** `~/RAGRAF/docs/STRATEGY-POSITIONING.md` — 200+ строк, 10 секций.

> **Когда стадия не нужна:** pet-проект, learning-проект, внутренний
> инструмент команды. Игры (GONKA/KNIFFEL/SOFIA) могут пропустить
> формальный STRATEGY-POSITIONING, оставив только USP в README.

---

## Структура документа

### 0. Executive summary

3-5 абзацев. Включает:
- **Ключевую позиционную находку.** Одна фраза: «X — это то-то, чего нет у Y/Z».
- **Три устойчивых ниши** одной строкой каждая.
- **IP-портфель** одной строкой.
- **Ценовая модель** одной строкой.
- **Контрольная метрика года.**

### 1. Ключевая позиционная находка

Формула в одну фразу, которую можно использовать на лендинге, в питче,
в заявке на грант. Пример из RAGRAF:

> «РАГРАФ — практическая реализация задачного подхода Гончарова-Свириденко
> в виде открытой операционной платформы для управления процессами IoT + люди».

Структура формулы: **«<Продукт> — <реализация чего> в виде <формы> для
<целевого применения>».**

### 2. Аудит продукта относительно теоретической рамки

Если у тебя есть **внешняя формальная теория** (Сибирская школа,
методология Agile/SAFe, ГОСТ-стандарт), сделай таблицу:

| Компонент рамки | Реализован? | Что есть | Чего не хватает |
|-----------------|-------------|----------|-----------------|
| Компонент 1 | ✅ полно | … | — |
| Компонент 2 | ⚠ частично | … | … |
| Компонент 3 | ❌ нет | — | … |

Это даёт roadmap «к полной реализации рамки». См. также
[knowledge/patterns/audit-vs-framework.md](../../knowledge/patterns/).

### 3. Конкурентный ландшафт

#### 3.1 Карта рынка по N сегментам

| Сегмент | Примеры | Что делают | Где пробел |
|---------|---------|-----------|------------|
| BRE/BPMS | ELMA365, Comindware | … | Семантика и IoT слабы |
| Цифровые двойники | Минстрой, Ростелеком | … | Двойник процесса нет |
| Тасктрекеры | Yandex Tracker, Jira | … | Триггер из физмира нет |

Не делай больше 5-6 сегментов — иначе теряется фокус.

#### 3.2 Сильные стороны продукта

Список из 5-8 пунктов, каждый — конкретная фича + почему конкуренты её не имеют.

#### 3.3 Слабые стороны

Честно. 3-5 пунктов. Это база для roadmap'а.

#### 3.4 Топ-3 угрозы

«Кто и как может закрыть нашу нишу за год».

### 4. Стратегия поиска ниши

#### 4.1 Три устойчивых ниши

Каждая ниша — отдельный абзац:
- **Кому продаём** (конкретный сегмент).
- **Какую боль закрываем.**
- **Каноническая клиентская ситуация** (1-2 предложения как сценарий).

#### 4.2 От чего отказываемся (явно)

Список из 4-5 пунктов «**не** конкурируем с …, потому что …».

Это так же важно, как сами ниши. См.
[knowledge/patterns/three-niches-rejection.md](../../knowledge/patterns/).

### 5. Уникальности, достойные регистрации

Если продукт коммерческий — план IP-портфеля:

| Тип охраны | Кандидаты |
|------------|-----------|
| Патент-изобретение (ст. 1350 ГК) | «Способ X с тех. результатом Y» |
| Свидетельство о госрегистрации ПО (ст. 1262 ГК) | 5+ модулей раздельно |
| Свидетельство на БД | seed-онтологии / контентные базы |
| Товарный знак (МКТУ 9, 42) | название продукта |
| Ноу-хау (98-ФЗ) | методики, скрытая логика |

И что **не патентуется** — отдельным списком, чтобы не подавать зря.

### 6. Ценовая стратегия

Три тира + платный пилот:

| Тир | Цена/год | Кому |
|-----|---------|------|
| Старт | 480-900 тыс. ₽ | Команда / малый бизнес |
| Бизнес | 2,4-4,8 млн ₽ | Средний бизнес |
| Энтерпрайз | от 8 млн ₽ | Крупный заказчик / город |
| Пилот | 250-400 тыс. ₽ | Доказать ROI за 4-8 недель |

Подробности — на стадии 3 (ECONOMICS).

### 7. Дорожная карта позиционирования (12-18 мес)

- Q1: что предъявляем
- Q2: первые внедрения
- Q3-Q4: масштабирование
- Метрика года: ARR ≥ X / NPS пилотов ≥ Y

### 8. Открытые вопросы

«Что мы НЕ знаем, и где это узнать». Это список ссылок на будущее
ресёрч, не отговорка.

## Когда стадию можно пропустить

| Тип проекта | Пропускать? |
|-------------|-------------|
| Внутренний инструмент / pet | ✅ да |
| Игра / pet-game | ✅ да (USP в README достаточно) |
| Заказной коммерческий | ❌ нет |
| Грантовый | ❌ нет (иначе нет шансов на оценку) |
| Open-source с коммерческим планом | ⚠ облегчённая версия |
