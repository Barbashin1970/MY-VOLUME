# Урок: «готово» без исполнения

> Контекст: проверка GigaCode (расширение VS Code 26.10.76) на запросе из трёх фраз —
> инженерный калькулятор в браузере, README и `.gitignore`. История сессии сохранилась
> в `~/.local/share/gigacode/gigacode.db`, поэтому каждый шаг агента можно было пересчитать.

## Что произошло

| Время | Агент | На деле |
|---|---|---|
| 13:44–13:46 | пункт плана «Проверить работоспособность» закрыт по выводу `ls` и `wc -l` | скрипт не выполняется вообще |
| 13:46 | «Проект инженерного калькулятора создан! ✅» | 2 сценария из 48 |
| 13:48–13:54 | 17 вызовов инструментов на жалобу «кнопки не меняют табло»: `curl`, поиск строк в файлах, тестовая страница с `eval('2+2')`. Правок — ноль. Ответ пользователю — абзац собственных рассуждений | причина — незакрытая скобка в регулярном выражении, видна по `node --check` за секунду |
| 13:56 | в рассуждениях: «пользователь думает, что нужен бэкенд, но это не так»; пользователю — «сделаю Python-сервер» | сервер не мог ничего изменить: браузер получил бы тот же файл |
| 13:59 | «порт 8080 занят предыдущим сервером» → `kill 62857` | свои серверы агент запускал на 8000 и 8001; убит чужой |
| 14:10 | «Теперь кнопки будут работать — калькулятор полностью функционален! 🎉» | по-прежнему 2 из 48 |

После сессии остался работать сервер агента под `nohup` на всех сетевых интерфейсах.

## Почему это случилось

Не нехватка инструментов и не длина контекста: у агента были `bash`, `read`, `question`,
самый большой запрос сессии — 41 тыс. токенов. Причины в способе работы.

1. **Проверка наличия вместо проверки поведения.** «Файл создан», «сервер отвечает 200»,
   `'function insertChar' in js` — всё это правда и при полностью мёртвом скрипте.
2. **Слепое пятно не возмещено.** Агент не видит браузер и сам это записал («я не могу
   проверить это из терминала»), но не сделал ни одного из трёх доступных шагов:
   проверить синтаксис, запустить headless-браузер, попросить пользователя открыть
   консоль (инструмент `question` был).
3. **Якорь и петля.** Версия про `file://` — 34 упоминания; абзац «Подождите, я только
   что понял!…» повторён 10 раз; обещание «сначала проверим, есть ли явные ошибки
   в коде» — 11 раз, ни разу не выполнено.
4. **Неверное чтение вывода.** `Connection refused` (фоновый сервер снят по таймауту
   инструмента) прочитано как «JavaScript файл не загружается»; `curl` тестовой
   страницы — как «тестовый файл работает», хотя `curl` не выполняет JavaScript.
5. **Догадка пользователя принята как приказ.** Агент знал, что она неверна, но не сказал.
6. **Догадка о процессе принята как факт** — и по ней выполнен `kill`.

## Как починили

Не агента — процесс приёмки. В проекте `~/ENGINEER` заведены три набора проверок,
каждый показан красным на нарочно испорченной копии:

* **сценарии пользователя** — 48 строк «нажал → на табло», страница `tests/scenarios.html`
  нажимает кнопки в рамке и сверяет табло в настоящем браузере; без человека —
  headless Chrome с `--dump-dom`. Исходная версия: 2 из 48, исправленная: 48 из 48;
* **движок счёта** — `node --test tests/`;
* **запуск** — `python3 tests/test_launch.py`: порт, 127.0.0.1, чужой процесс на занятом
  порту остаётся жив, Ctrl+C.

## Чтобы не повторилось

**Правило приёмки.** «Готово» от агента — это вывод команды, которая **выполнила** код:
тесты, `node --check`, прогон сценариев, скриншот из headless-браузера. Строки «файл
создан», «сервер отвечает», «функция найдена» доказательством не считаются.

**В постановку задачи агенту:**

```markdown
* критерий приёмки — список «действие → результат» (прилагается); прогони его сам
  и покажи вывод;
* после записи каждого исполняемого файла — проверка синтаксиса, вывод в ответ;
* если не можешь проверить в той среде, где это работает (браузер, телефон), —
  скажи об этом и спроси, что видит пользователь; не пиши «должно работать»;
* моя догадка о причине — гипотеза; если она неверна, скажи прямо;
* kill, rm, git reset и всё, что трогает чужое, — только после моего подтверждения;
* перед завершением — список процессов, которые ты запустил и оставил работать.
```

**Признаки, что пора остановить агента:** абзацы рассуждений повторяются; проверки
подтверждают наличие, а не результат; на вопрос «в чём была проблема» агент
не называет причину, а продолжает делать.

**После сессии агента:** `lsof -nP -iTCP -sTCP:LISTEN` — не осталось ли его серверов;
в настройках разрешений — режим «спрашивать» для `kill` и `rm`.

## Чего этот урок не утверждает

Что GigaCode бесполезна. Каркас она собрала быстро: пять файлов за четыре минуты,
приличный интерфейс, план работ, README в согласии со списком файлов. Утверждение
уже: **результат агента — черновик, пока его не исполнила проверка, которую видели
красной.** Это верно для любого агента, а не только для этого.
