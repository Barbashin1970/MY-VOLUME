# ADR-003: Билингвальный README

## Контекст

Российский рынок (госзаказ, гранты, корпоративы) требует русский
текст с привязкой к ГОСТ. Open-source комьюнити и международные
коллеги читают английский. POLINOM продемонстрировал, что **обе
аудитории могут быть в одном репо** без конфликта.

## Решение

**Для проектов категории A (заказной коммерческий) и C
(научно-инструментальный) — пара:**

- `README.md` — русский, для российского рынка / госзаказа / гранта.
- `README-en.md` — английский, для open-source / международного
  комьюнити.

В верхней части каждого — кросс-ссылка:

```markdown
> English version: [`README-en.md`](README-en.md).
> Russian version: [`README.md`](README.md).
```

Английский README **не дословный перевод**, а **сжатая версия** (50-70%):
без ГОСТ-ссылок, без формальностей. Только техническая сторона.

## Когда **не** делать билингву

- Pet-проект (категория B).
- Внутренний инструмент команды.
- Игра только для российского рынка.

## Альтернативы

| Вариант | Почему не выбрали |
|---------|-------------------|
| Только английский | Теряем российский рынок и гранты |
| Только русский | Теряем open-source комьюнити |
| Перевод по требованию | Никто не переведёт когда нужно |
| i18n внутри README через теги | Уродует синтаксис, GitHub плохо рендерит |

## Последствия

### Позитивные
- POLINOM имеет ~10x больше внешних звёзд после публикации `README-en.md`.
- AI-агент (Claude / Cursor) при инициализации проекта видит обе версии.

### Негативные
- Двойная работа при обновлении. Решается дисциплиной:
  обновляешь русский → коротко переписываешь английский (не дословно).

### Нейтральные
- Раздельные `README-en.md` файлы лучше, чем `README.en.md` —
  GitHub лучше рендерит первый вариант в file-tree.
