# projects/

Здесь — **карточки проектов**, по одной папке на проект. Это «зеркало» того,
что лежит в коде в `~/<PROJECT>/`, но в форме, удобной для размышлений и
для AI-ассистента.

> **Важно:** код живёт не здесь. Тут только md-документация и заметки.
> Папка `~/LEYKA/` остаётся источником правды для кода, а
> `projects/active/leyka/` — источником правды для контекста проекта.

---

## Структура

```
projects/
├── README.md           ← этот файл
├── _template/          ← скелет нового проекта (копируй целиком)
├── active/             ← всё, над чем сейчас идёт работа
│   └── <project-slug>/
│       ├── README.md   ← обзорная карточка (см. templates/project.md)
│       ├── arc.md      ← архитектура (одна страница)
│       ├── backlog.md  ← задачи
│       ├── bugs.md     ← локальные баги и фиксы
│       └── decisions.md← локальные решения
└── archive/            ← завершённые/приостановленные проекты
```

## Когда создавать новую карточку

1. Стартуешь новый проект (даже идею) → копируй `_template/` →
   `active/<slug>/`.
2. Идея отложена → перенеси в `archive/`, добавь в frontmatter
   `status: paused`.
3. Завершил/выкатил и больше не трогаешь → `archive/`, `status: archived`.

## Что класть в карточку проекта

| Файл | Что внутри |
|------|-----------|
| `README.md` | Обзор: цель, статус, ссылки. **Это первое, что прочитает Claude / коллега.** |
| `arc.md` | Архитектура в одну страницу: схема + критические решения. Без воды. |
| `backlog.md` | Открытый список задач. Можно вести как Kanban-таблицу. |
| `bugs.md` | Что сломалось и как починили (с датами). Это **сырьё для уроков** |
| `decisions.md` | Локальные ADR — пока решения не созрели до публикации в `docs/decisions/` |

## Что **не** класть

- Длинные технические простыни. Это пусть живёт в `~/<PROJECT>/docs/` рядом с кодом.
- Дубликат `README.md` из репозитория. Здесь — твой **внутренний** README,
  тот что в репо — для пользователя кода.
- Секреты, ключи, пароли. **Никогда.**
- Бинарники. В `../assets/`.

## Промоутирование знания вверх

Каждый раз, когда закрываешь итерацию, спрашивай: «что из этой папки
применимо к следующему проекту?»

| Из `projects/<x>/...` | Куда промоутить |
|-----------------------|-----------------|
| `bugs.md` — повторимый урок | [knowledge/lessons/](../knowledge/lessons/) |
| `decisions.md` — системное решение | [docs/decisions/](../docs/decisions/) |
| Кусок `arc.md` — типовой паттерн | [knowledge/patterns/](../knowledge/patterns/) |
| Рецепт из любого файла | [knowledge/skills/](../knowledge/skills/) |
| Новый термин | [concepts/](../concepts/) |

**Источник остаётся в `projects/`, обобщение — в `knowledge/`. Никогда не
удаляй проектную запись — она доказательство, что урок реальный.**
