# Модели команд

**6 классических моделей.** Каждая отвечает на свой вопрос. Вместе
они дают полную картину «как команда устроена и куда движется».

## Карта моделей

| Модель | Что отвечает | Применять когда |
|--------|--------------|-----------------|
| **Tuckman** | На какой стадии команда сейчас | Новая команда / конфликты |
| **DISC** | Какие типы людей в команде | Подбор / коммуникация |
| **PAEI Адизес** | Кого не хватает в команде | Найм / распределение ролей |
| **Belbin** | Какие командные роли заняты | Сборка проектной команды |
| **Servant Leadership** | Какой стиль лидерства уместен | Лидер выбирает свою роль |
| **McKinsey 7S** | Согласована ли организация | Аудит компании / трансформация |

## 1. Tuckman — жизненный цикл команды (1965)

5 стадий, через которые проходит **любая** новая команда:

| Стадия | Что происходит | Длительность |
|--------|---------------|--------------|
| **Forming** (формирование) | Знакомство, осторожность, ориентация на лидера | Дни |
| **Storming** (конфликт) | Споры о ролях, борьба за влияние, разочарование | Недели |
| **Norming** (нормирование) | Правила выработаны, доверие растёт | Недели-месяцы |
| **Performing** (эффективность) | Команда работает сама, лидер фасилитирует | Месяцы-годы |
| **Adjourning** (расформирование) | Проект закрыт, команда расходится | Дни |

> Главный сюрприз: **storming неизбежен**. Команда, которая «всегда дружная», просто избегает важных решений.

## 2. DISC — 4 типа поведения

Модель Уильяма Марстона (1928), адаптирована для бизнеса.

| Тип | Девиз | Сильные стороны | Конфликт с |
|-----|-------|------------------|------------|
| **D — Dominance** | «Что делаем сейчас» | Решительность, скорость | I, S |
| **I — Influence** | «Кто с нами» | Энтузиазм, нетворкинг | C |
| **S — Steadiness** | «Как сохранить стабильность» | Терпение, лояльность | D |
| **C — Compliance** | «Сделать правильно» | Точность, анализ | I |

**Применение:** на стендапе D говорит первый, I — самый громкий, S — самый молчаливый, C — задаёт неудобные вопросы. Знаешь типы — знаешь, как услышать тихих.

## 3. PAEI — Адизес (1979)

4 роли, которые **обязательны** в любой команде:

| Буква | Роль | Что делает |
|-------|------|-----------|
| **P — Producer** | Производитель | Делает работу, краткосрочный результат |
| **A — Administrator** | Администратор | Систематизирует, процессы, документация |
| **E — Entrepreneur** | Предприниматель | Видение, долгосрочные изменения |
| **I — Integrator** | Интегратор | Объединяет людей, устраняет конфликты |

**Главное:** один человек **не** может быть всем (PAEI). Адизес говорит, что идеальный руководитель — миф. Нужна команда, дополняющая друг друга.

**Сигналы дефицита:**
- Нет P → много планов, ничего не делается
- Нет A → хаос, теряются обещания
- Нет E → застой, нет инноваций
- Нет I → конфликты, текучка

## 4. Belbin — командные роли (1981)

9 ролей по тестированию в Cambridge. Сокращённо:

| Категория | Роли | Что делает |
|-----------|------|-----------|
| **Мыслительные** | Plant / Monitor / Specialist | Идеи, анализ, экспертиза |
| **Действующие** | Implementer / Completer / Shaper | Воплощение, доводка, давление |
| **Социальные** | Coordinator / Teamworker / Resource | Координация, гармония, контакты |

**Применение:** перед запуском проекта прогнать команду через тест Belbin. Если 4 из 5 «исполнители» — будет много действий и мало идей.

## 5. Servant Leadership — Роберт Гринлиф (1970)

> «Лидер существует для команды, а не команда для лидера».

| Признак | Что значит |
|---------|-----------|
| **Слушает первым, говорит вторым** | Команда формулирует, лидер уточняет |
| **Убирает препятствия** | Главная задача — чтобы команда работала эффективнее |
| **Развивает людей** | Делает себя ненужным |
| **Принимает решения не из «эго», а из общей цели** | Не «как я хочу», а «как лучше для дела» |

Контраст с **командно-административным** стилем: «я сказал — вы делаете».

## 6. McKinsey 7S — организационная модель (1980)

7 элементов, которые должны быть согласованы:

```
        Shared Values
         (центр)
            │
   ┌────────┼────────┐
   │        │        │
Strategy  Structure  Systems   (жёсткие)
   │        │        │
   └────────┼────────┘
            │
   ┌────────┼────────┐
   │        │        │
  Style    Staff    Skills     (мягкие)
```

| S | Что |
|---|-----|
| **Strategy** | Что мы делаем для достижения целей |
| **Structure** | Кто кому подчиняется |
| **Systems** | Процессы, инструменты |
| **Skills** | Что команда умеет |
| **Staff** | Кто работает (количество, опыт) |
| **Style** | Как принимаются решения |
| **Shared Values** | Что важно (культура) |

**Главное:** если 7S не согласованы — стратегия не работает. Пример: стратегия «инновации», структура иерархическая, стиль авторитарный → инноваций не будет.

## Применение в твоих проектах

| Ситуация | Какие модели брать |
|----------|-------------------|
| **Новая команда на RAGRAF** | Tuckman (готовиться к storming) + Belbin (сбалансировать роли) |
| **Конфликт в команде LEYKA** | DISC (понять типы) + PAEI (кого не хватает) |
| **Олег как соло-проект (POLINOM, SOFIA)** | PAEI: сам производишь (P), сам себе администратор (A), сам себе предприниматель (E). I не нужен — нет команды. Можно дольше. |
| **Заказчик в кризисе** | McKinsey 7S — найти, где рассогласование |
| **Я-лидер в команде** | Servant Leadership как ориентир |

## Антипаттерны

❌ **Применять всё сразу** — паралич анализа. Брать одну модель под одну ситуацию.

❌ **Жёсткая привязка человека к типу** — DISC и Belbin это **роли в контексте**, не диагнозы. Один человек в разных проектах играет разные роли.

❌ **Tuckman без storming** — пропуск этой стадии = подавленные конфликты, выстрел через год.

❌ **PAEI как «найди идеального руководителя»** — Адизес говорит обратное: идеального нет, нужен баланс.
