# Стадия 4 — Техническое задание (ГОСТ 19.201-78)

**Вход:** STRATEGY-POSITIONING + ECONOMICS закрыты.
**Выход:** `TZ_<PROJECT>_GOST19.md` или `TZ_<PROJECT>.md`.
**Время:** 3-5 дней.
**Эталон:** `~/RAGRAF/docs/TZ_RAGRAF.md`, `~/LEYKA/docs/LEYKA_TZ_GOST19.md`.

> ТЗ — **формальный документ**. Его согласует заказчик / куратор /
> руководитель. После согласования он **залочен** — изменения только
> через `ChangeRequest` в `decisions.md`.

### Обозначение документа

Класс ТЗ — обычно `ТЗ`. Полное обозначение:
`<СОКР_ПРОЕКТА>.ТЗ.NNN-YYYY` или `<CODE>-ТЗ`.

Примеры:
- `РГРФ-02-01-01-1/1-ТЗ` (RAGRAF)
- `LEYKA.TZ.001-2026`

## Стиль письма (по `SKILL-GOST-19.md` из RAGRAF)

- **Русский язык** для всего пользовательского текста.
- **Формальный, безличный** в требованиях: «Программа предназначена
  для…», «При сбое сервер возвращает 503».
- **Активный «вы»-залог** в шагах: «Нажмите кнопку».
- **Без жаргонизмов и шуток.** Если хочется пояснить «вживую» —
  выноси в README или SKILL-*.md.
- **При первом упоминании** — полное название, потом сокращение в
  скобках: «Цифровой регламент (далее — регламент) …».
- **Англицизмы** оставляем (Flow, SHACL, ETL) — не русифицируй.
- **Внутрипроектные термины** (Twin, Live ETL) — пишем как в коде,
  в кавычках или курсивом при первом появлении.

## Таблицы и диаграммы

- **Таблица побеждает абзац**, если есть 3+ параллельных фактов с
  одинаковой структурой.
- **Mermaid** для диаграмм (`flowchart`, `stateDiagram-v2`, `erDiagram`,
  `sequenceDiagram`). GitHub рендерит нативно.
- **ASCII-псевдографика** `┌─┐│` — **запрещена** (плохо на мобильных).
- **Скриншоты не вставляем** — UI меняется быстрее документа, даём
  название экрана и маршрут.

## Полный комплект ГОСТ-19 — что ещё может понадобиться

ТЗ — только один документ из комплекта. На стадии 7 (см.
[07-gost-19-doc-set](07-gost-19-doc-set.md)) появятся ещё:

| ГОСТ | Класс | Документ | Когда нужен |
|------|-------|----------|-------------|
| 19.201-78 | ТЗ | Техническое задание | **Сейчас (стадия 4)** |
| 19.505-79 | РО | Руководство оператора (пользователя) | Перед релизом |
| 19.503-79 | РС | Руководство системного программиста (админа) | При multi-user |
| 19.502-78 | ИУ | Инструкция по установке | При пилоте |
| 19.301-79 | ПМИ | Программа и методика испытаний | При формальной приёмке |

Прочие ГОСТ-19 (текст программы, описание программы, спецификация)
**не оформляем** — они нужны только при классической поставке
заказного ПО.
