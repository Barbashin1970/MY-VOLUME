# Pattern: Gated Funnel + Scoring Table

Воронка отбора кандидатов из многих по **жёстким последовательным гейтам**
с hard-kill правилами и единой scoring-таблицей. Приём для исследований
вида «отобрать лучшего кандидата из множества по дорогим в проверке критериям».

## Проблема

Когда кандидатов много (идеи, ниши, ключевые слова, библиотеки, вендоры),
а полная оценка каждого дорогая, наивный подход — оценить всех целиком —
сжигает время на заведомо непроходных вариантах. Нужно отсеивать **рано и дёшево**,
но при этом не терять воспроизводимость и не подгонять оценку под желаемое.

## Решение (идея)

1. **Линеаризуй критерии в воронку гейтов**, отсортированную по
   «дёшево проверить / рано отсеивает» вперёд. Дешёвый, но решающий критерий
   (1.3 «сводимо к одной функции?») идёт раньше дорогого keyword research.
2. **Каждый гейт — hard-kill правило** с явным порогом, не «вайбом»:
   провал → drop кандидата либо branch назад с новым входом. «Никогда не
   пропускай гейт — в этом весь смысл, остановиться рано».
3. **Единая scoring-таблица** — одна строка на кандидата, колонка на гейт.
   Никаких throwaway-файлов: добавляй/обновляй строки по ходу.
4. **Композитный score из взвешенных под-оценок** (0-10 рубрики, привязанные
   к сигналам) **минус red-flag штрафы** → порог-вердикт (GO / NEEDS-WORK / NO-GO).
5. **Decision tree на провал гейта** — заранее прописано, куда падать
   (другой кандидат / branch на ранний гейт / hard stop).

## Диаграмма

```
кандидаты ──► [гейт 1: дёшево, отсеивает] ──fail──► drop / branch
                     │ pass
                     ▼
              [гейт 2] ──fail──► drop / branch назад
                     │ pass
                     ▼
                    ...
                     │ pass всех
                     ▼
        scoring = Σ wᵢ·scoreᵢ − штрафы ──► порог ──► GO / NEEDS-WORK / NO-GO
                     │
                     └──► строка в единой таблице (1 кандидат = 1 строка)
```

## Когда **не** применять

- **Мало кандидатов / дешёвая полная оценка** — воронка лишь добавляет
  бюрократии; оцени всех сразу.
- **Критерии не независимы / нелинейны** — если провал гейта 2 меняет смысл
  гейта 5, жёсткая последовательность врёт; нужна совместная оценка.
- **Цель — не отбор, а проектирование** — паттерн выбирает из готовых
  вариантов, он не генерирует решение.
- **Пороги нельзя обосновать сигналами** — без анкеровки рубрик к измеримому
  получится псевдо-объективность («score 7.3» из воздуха).
