# Стадия 9 — Устав, отчёт, рост, IQ-roadmap

**Вход:** продукт в эксплуатации (внутренней, пилотной или внешней).
**Выход:** регулярно — `CHARTER.md` (раз в год), `ANNUAL-REPORT.md`
(раз в год/квартал), `IQ-roadmap.md` / `BACKLOG.md` (живой).
**Эталоны:**
- `~/LEYKA/docs/SKILL-PROJECT-CHARTER-AND-REPORTS.md` — анализ Устав/Отчёт
- `~/NSK_OpenData_Bot/IQ-roadmap.md` — карта развития по фазам и метрике IQ

> Это стадия **долгого горизонта**. Документы здесь нужны не для
> «выпустить продукт», а для **управления продуктом в эксплуатации**:
> отчётность перед заказчиком, планирование роста, обоснование бюджета.

---

## A. Устав проекта (Project Charter) — для гос/корп заказчика

Структура устава (по реальному Уставу проекта «Сигма 2025» НГУ —
LEYKA SKILL-PROJECT-CHARTER):

| § | Раздел | Тип данных |
|---|--------|-----------|
| 1 | Описание проекта и решаемых задач | свободный текст (1-2 абзаца) |
| 2 | Продукт и потребители | таблица: продукт / описание / стейкхолдеры |
| 3 | Возможности внедрения по годам | bullets с разделением по году |
| 4 | Исполнители (с FTE-ставкой) | таблица: ФИО / подразделение / задачи / ставка |
| 5 | Общий план работ (этапы) | text по годам с этапами 1-4 |
| 6 | Календарный план на год | таблица: мероприятие / срок начала / окончания / результат |
| 7 | План показателей KPI | таблица: общий план + фреймворки + РИД + публикации |
| 8 | Ограничения / Бюджет (КОСГУ) | таблица КОСГУ: ст.211 / 213 / 222 / 226 / 310 / 320 / 340 |
| 9 | Периодичность отчётности | строка |
| 10 | Контактное лицо | ФИО / телефон / email |
| 11 | Виза руководителя + лист согласования | подписи: руководитель, директор центра, главбух, ПФУ, замдиректора |

**Особенность КОСГУ:** российский бюджет проекта **не одна сумма**, а
разбит по статьям расходов классификации сектора госуправления (КОСГУ).
LEYKA SKILL это явно отмечает.

> **Если работаешь с НГУ/НГТУ/госконтрактом:** см.
> [concepts/kosgu.md](../../concepts/) — статьи 211 (з/п), 213
> (начисления), 222 (транспорт), 226 (прочие услуги), 310 (основные
> средства), 320 (нематериальные активы), 340 (расходные материалы).

## B. Годовой отчёт (Annual Report) — выгрузка фактов

7 разделов (по реальному Отчёту LEYKA):

| § | Раздел | Источник данных |
|---|--------|------------------|
| 1 | Постановка задач по уставу | калька с Устава §6 |
| 2 | Результаты работ группы разработки | по этапам, что сделано |
| 3 | Регистрация РИД (программы ЭВМ) | реквизиты Роспатент: №, дата заявки, авторы |
| 4 | Отчёт о публикациях | таблица: статья / журнал-статус / авторы / DOI |
| 5 | Отчёт о регистрации РИД | таблица: РИД / тип / статус |
| 6 | Результаты выполнения KPI | таблица: показатель / план / результат / вывод (выполнен/не выполнен/частично N%) |
| 7 | Заключение | текст: что сделано, что переходит, что прилагается |
| подвал | Подпись руководителя проекта | подпись |

**Ключевая идея:** Отчёт **полностью генерируется** из накопленных в
системе задач + KPI + Showcase. Если вы сделали грамотный таск-трекер
(LEYKA-style), отчёт собирается автоматически.

## C. IQ-roadmap — как модерировать рост (NSK-стиль)

Это **уникальный паттерн Олега**: моделировать рост продукта как
прохождение этапов с **числовой метрикой суммарного интеллекта**.

Пример из `~/NSK_OpenData_Bot/IQ-roadmap.md`:

> «Текущий охват: ~35-40 баллов из 120 (хорошо покрыты ЖКХ, экология,
> транспорт, безопасность). Цель к ПМЭФ: ~60-70 баллов —
> среднероссийский уровень (среднее 2024 = 61 балл)».

### Структура IQ-roadmap

#### 1. Метрика и её источник

«IQ-индекс городов Минстроя» в случае NSK — внешняя стандартизованная
метрика. Можно использовать и кастомную.

#### 2. Карта направлений (где каждое — отдельное измерение IQ)

| # | Направление | Текущий статус | Приоритет |
|---|-------------|----------------|-----------|
| 1 | Городское управление | ✅ Частично | — |
| 2 | Умное ЖКХ | ✅ Реализовано | — |
| 3 | Городская среда | ⚠ Частично | Фаза 3 |
| 4 | Умный транспорт | ✅ Частично | Фаза 1 |
| … | … | … | … |

#### 3. Фазы — последовательные этапы роста

```markdown
## Фаза 1 — «Умный транспорт» (текущая)
**Статус: в работе**
**Ожидаемый прирост IQ: +5 баллов**

| Задача | Источник | Сложность | Файлы |
| … | … | … | … |
```

Каждая фаза включает:
- Список задач с источниками данных
- Оценка сложности (Низкая/Средняя/Высокая)
- Файлы, которые надо создать/расширить
- Ожидаемый прирост метрики

#### 4. Оценка прироста IQ по фазам

```markdown
| Фаза | +баллов (оценка) | Итого |
|------|------------------|-------|
| Базовый | ~35 | 35 |
| Фаза 1 | +5 | 40 |
| Фаза 2 | +10 | 50 |
| Фаза 3 | +12 | 62 |
| Фаза 4 | +13 | 75 |
| Фаза 5 | +15 | 90 |
```

Это даёт **визуальный roadmap роста** с конкретной целью и проверяемой
метрикой на каждом шаге.

#### 5. Технический шаблон расширения

Quick reference из 5-7 шагов: «как добавить новый топик в систему».
NSK имеет:
```
1. Данные: добавить в config/datasets.yaml ИЛИ src/<topic>_data.py
2. Роутер: _route_<topic>() + регистрация
3. Планировщик: ветка в make_plan()
4. Исполнитель: execute_<topic>()
5. API: ветка if topic == "<topic>":
6. Рендер: renderTopic() + dispatch
```

## E. Как стадия 9 связана с моделью данных

Из LEYKA SKILL-PROJECT-CHARTER §4 — какие сущности должны быть в БД,
чтобы Устав и Отчёт **генерировались автоматически**:

- `Project` (название, описание, даты, бюджет)
- `ProjectMember.fte` (с дробной ставкой) — для §4 Устава
- `ProjectMilestone` (этапы) — для §5-6 Устава
- `KpiCenterTarget` + `ProjectKpiCommitment` + `KpiAchievement` — для §7
- `ProjectBudgetItem` (по КОСГУ) — для §8
- `ShowcaseAsset` (публикации, РИД) — для §3-5 Отчёта
- `ProjectApproval` (лист согласования) — для §11

Если строишь систему с расчётом на гос/корп заказчика — заложи это
в модель сразу.
