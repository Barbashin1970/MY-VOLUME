# Стадия 7 — Комплект документации по ГОСТ-19

**Вход:** реализация близка к приёмке.
**Выход:** 4-5 ГОСТ-19 документов в `docs/`.
**Время:** 1-2 недели для полного комплекта.
**Эталон:** `~/LEYKA/docs/LEYKA_*_GOST19.md` (5 файлов — полный комплект).

> ГОСТ-19 — формальная серия стандартов «единая система программной
> документации». В академической / госзаказной среде комплект может
> быть **обязательным результатом** этапа НИР/НИОКР.

---

## Какие документы входят в комплект

| Документ | ГОСТ | Класс | Когда обязателен | Эталон |
|----------|------|-------|------------------|--------|
| Техническое задание | 19.201-78 | `ТЗ` | Стадия 4 (всегда) | `LEYKA_TZ_GOST19.md`, `RAGRAF/docs/TZ_RAGRAF.md` |
| Программа и методика испытаний | 19.301-79 | `ПМИ` | При формальной приёмке | `LEYKA_PMI_GOST19.md` |
| Инструкция по установке | 19.502-78 | `ИУ` | При поставке заказчику | `LEYKA_InstallManual_GOST19.md` |
| Руководство системного программиста (админа) | 19.503-79 | `РС` | При multi-user деплое | `LEYKA_AdminGuide_GOST19.md` |
| Руководство оператора (пользователя) | 19.505-79 | `РО` | Перед релизом | `LEYKA_UserManual_GOST19.md`, `RAGRAF_UserManual_GOST19.md` |

**Что НЕ оформляем:** «Текст программы» (19.401), «Описание программы»
(19.402), «Спецификация» (19.202) — нужны только при классической
поставке заказного ПО, заказчик ≠ разработчик. Для open-source и
команды разработки они избыточны.

## Структура отдельных документов

### ТЗ (19.201-78) — см. отдельный плейбук

Полная структура — в [04-tz-and-gost-19](04-tz-and-gost-19.md).

### РО — Руководство оператора (19.505-79)

| § | Раздел |
|---|--------|
| 1 | Назначение программы |
| 2 | Условия выполнения программы (среда, требования к ПК) |
| 3 | Выполнение программы — **главная часть**, по разделам интерфейса |
| 3.N | Сценарий N: пошагово, как пользователь делает |
| 4 | Сообщения оператору (что значит каждая ошибка) |
| Прил. А | Роли и права |
| Прил. Б | Маршруты UI (URL-структура) |
| Прил. В | Глоссарий терминов |

**Стиль:** «вы»-инструктивный. «Нажмите кнопку», «Введите…».
**Без скриншотов** — UI меняется. Описывай маршрутом и именем кнопки.

### РС — Руководство админа (19.503-79)

| § | Раздел |
|---|--------|
| 1 | Назначение |
| 2 | Требования к среде (ОС, БД, сеть) |
| 3 | Установка и развёртывание |
| 4 | Конфигурация (`.env`, конфиги, секреты) |
| 5 | Запуск и остановка |
| 6 | Резервное копирование и восстановление |
| 7 | Обновление версии |
| 8 | Логи и мониторинг |
| 9 | Решение типовых проблем |

### ИУ — Инструкция по установке (19.502-78)

Короче, чем РС. Только установка + первый запуск. Если она помещается
в раздел README — отдельный документ не нужен.

### ПМИ — Программа и методика испытаний (19.301-79)

| § | Раздел |
|---|--------|
| 1 | Объект испытаний |
| 2 | Цели испытаний |
| 3 | Программа испытаний (список тестов) |
| 4 | Методика испытаний (для каждого теста: вход, действия, ожидаемый результат, критерий прохождения) |
| 5 | Приёмо-сдаточные результаты |

Формат теста:
```markdown
### Тест 3.1.2 — Создание задачи через API

**Вход:** валидный JWT, JSON с `title`, `project_id`.
**Действия:** POST `/api/tasks` с указанным body.
**Ожидаемый результат:** HTTP 201, в БД появилась запись, response
содержит `id` (UUID).
**Критерий прохождения:** все три факта подтверждены.
```
