# Skill: Адверсариальный фактчек цитат

> **Паттерн:** один агент на одну ссылку, скептический дефолт «не найдено»,
> проверка по СЫРОМУ arXiv API (не через LLM-обёртку), затем синтез правок.

## Когда применять

Если перед тобой документ (ТЗ, НИР, статья, презентация) со списком научных
ссылок — особенно если он **редактировался ИИ** или «проверен агентами».
LLM-аудиты систематически: (1) выдумывают правдоподобные arXiv ID; (2) неверно
атрибутируют авторов; (3) искажают год (путают дату ревизии с публикацией);
(4) приписывают реальной работе чужую тему/цифры. Глазами это не ловится —
ссылка «выглядит настоящей».

## Как применять

Воркфлоу: per-source агент + барьер + синтез. Ключ — **скептический дефолт** в
промпте и проверка по `export.arxiv.org/api` (HTML-страницы и WebFetch иногда
галлюцинируют, сырой XML — нет; контроль фейковым ID даёт `totalResults=0`).

```js
// Workflow: по одному агенту на источник, параллельно
const CITATIONS = [ {key, cite, claim, arxiv}, ... ]
const verdicts = await parallel(CITATIONS.map(c => () => agent(
  `Ты строгий фактчекер. Проверь ОДИН источник через WebSearch/WebFetch
   (arxiv.org, doi.org, eudml, eur-lex, iso.org).
   Источник: ${c.cite}; как используется: ${c.claim}; заявленный ID: ${c.arxiv}
   Проверь: существование, точность arXiv ID, год, авторов, цифры/тему.
   СКЕПТИЧЕСКИЙ ДЕФОЛТ: нет конкретного подтверждения (живая страница
   arXiv/DOI с совпадающими метаданными) → status="not_found".
   Правдоподобный вид ID НЕ подтверждение.`,
  { label: `cite:${c.key}`, schema: CIT_SCHEMA }   // status, found, year/idCorrect, claimAccurate, recommendation, evidence
)))
// затем один синтез-агент → список точных правок «строка → что на что → чем подтверждено»
```

Проверка arXiv без LLM-посредника (самый надёжный шаг):

```bash
curl -s "http://export.arxiv.org/api/query?id_list=2603.24579"
# totalResults=1 + <title>/<author>/<published> → реальна; =0 → выдумана
```

## Почему именно так

- **Один агент на ссылку** — изоляция: агент не «подгоняет» вердикт под соседние
  цитаты, не экономит усилия на пачке. Это та же информационная асимметрия, что
  и в MARCH-верификации.
- **Скептический дефолт** — без него LLM по умолчанию подтверждает «похожее на
  правду». Дефолт «not_found, пока не доказано» переворачивает bias.
- **Сырой arXiv API** — WebFetch резюмирует через маленькую модель, которая может
  досочинить метаданные; XML API — факт.

## Известные подводные камни

- Год по префиксу arXiv ID (2512 = дек 2025) ≠ год «ревизии» на странице.
  Канонический год — по префиксу/первой подаче.
- «Реальна» ≠ «трактовка верна»: источник может существовать, но документ
  приписывает ему чужую тему (в кейсе ZET так было с AAFLOW и Agentic UQ).
- 2 автора → «X & Y», не «X et al.».
- Не-arXiv (ГОСТ/ISO/законы) — проверять по издателю/реестру (iso.org даёт 403
  ботам — идти через зеркала Microsoft Learn/ANSI/EUR-Lex).
- Один упавший агент (StructuredOutput retry cap) — добей ссылку вручную, не
  бросай дыру.
