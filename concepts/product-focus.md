# Product Focus

**Гибкая методология управления продуктами**, которая позволяет
использовать **наиболее эффективные методы и подходы** продакт-менеджмента
вместе, формируя стратегические фокусы и кратчайший путь от идеи
продукта к лидерству на рынке.

**Главная боль, которую решает:** в продакт-менеджменте 100+ инструментов
с пересекающимися именами (фреймворки / методы / модели / канвасы /
концепции). Эксперты с трудом разбираются в терминологии. Product Focus
даёт **систему отбора по Парето** — берём не всё, а самое эффективное
для конкретной ситуации.

---

## 4 базовые модели

### Модель 1 — Структура методологии (пирамида)

Любая методология строится из 4 слоёв:

```
       ┌─────────────────────┐
       │ Ценности и принципы │  ← документ «Политика»
       └─────────────────────┘
       ┌─────────────────────┐
       │       Модели        │  ← документ «Положения»
       └─────────────────────┘
       ┌─────────────────────┐
       │       Методы        │  ← «Регламенты», «Инструкции»
       └─────────────────────┘
       ┌─────────────────────┐
       │     Инструменты     │  ← «НСИ», «Шаблоны»
       └─────────────────────┘
```

**Пример заполнения** под «Клиент в центре / Понимание клиента»:

| Слой | Вариант 1 | Вариант 2 | Вариант 3 |
|------|-----------|-----------|-----------|
| Модели | Cynefin | JTBD | Пропасть Мура |
| Методы | Scrum | Глубинное интервью | RICE приоритезация |
| Инструменты | Lean Canvas | Скрипт глубинного интервью | Шаблон карты стейкхолдеров |

**Главная идея:** **модели конкурируют, инструменты можно смешивать.**
Если выбрал JTBD как модель — основной метод JTBD-интервью, но
«Наблюдение» из Дизайн-мышления и «карта стейкхолдеров» из любого
другого подхода — добавить можно.

### Модель 2 — Фокусы создания продукта (4 фокуса + стратегия)

Чтобы создать **востребованный** продукт, нужно совместить 4 фокуса:

```
                ┌─────────┐
                │ Тренды  │
                │ как     │
                │ зараб.  │
                │ долго?  │
                └────┬────┘
                     │
       ┌────────┐    ▼    ┌────────┐
       │Продукт │  Стратегия │ Клиент │
       │что    ◄─как стартовать?─► какие  │
       │будет в │            │ потреб.│
       │спросе? │            │ ?      │
       └────────┘    ▲    └────────┘
                     │
                ┌────┴────┐
                │ Бизнес  │
                │ как зар.│
                │ больше? │
                └─────────┘
```

| Фокус | Ключевой вопрос | Что внутри |
|-------|----------------|------------|
| **Клиент** | Какие потребности у клиентов? | сегменты, задачи (jobs), контексты покупки |
| **Продукт** | Что будет пользоваться спросом? | технологии, функции, дизайн |
| **Бизнес** | Как зарабатывать больше? | объём рынка, конкуренты, каналы, цена, бизнес-модель |
| **Тренды** | Как зарабатывать длительное время? | технологические + поведенческие + рыночные тренды |
| **Стратегия** | Как стартовать? | пересечение всех 4 фокусов |

**Можно начинать с ЛЮБОГО фокуса**, не обязательно с «Клиента»:

- **Из тренда:** Интернет-банкинг 2000-х — поймали тренд интернета,
  построили продукт, потом изучили клиента.
- **Из технологии:** Apple iPod — увидели прототип компактного носителя
  Toshiba (Технология), получили эксклюзив, потом создали сегмент рынка.
- **Из бизнеса:** нашли «голубой океан» с большим объёмом → пошли
  к клиентским исследованиям → MVP → тренд.

**Инструменты на каждый фокус:**

| Фокус | Инструменты |
|-------|-------------|
| Клиент | JTBD, Дизайн-мышление |
| Продукт | MVP, Kano |
| Бизнес | TAM/SAM/SOM, юнит-экономика |
| Тренды | Трендвотчинг, Форсайты |
| Стратегия | Lean Canvas, Blue Ocean Strategy |

### Модель 3 — Фокусы управления (3 фокуса)

Создание продукта отвечает на «**ЧТО?**». Управление командой —
на «**КАК?**».

| Фокус | Описание | Инструменты |
|-------|----------|-------------|
| **Ритм** | Стратегия / тактика / задачи / гипотезы | OKR, Agile, Канбан, Скрам, Growth-hacking, HADI цикл |
| **Команда** | Лидер, роли, коммуникации, мотивация, культура | Модель Такмана, Спиральная динамика, DISC, PAEI (Адизес: P/A/E/I), Модель Белбина, Servant Leadership |
| **Интеграция** | Процессы компании, IT, стейкхолдеры, оргструктура | Портфельное управление, value chain |

> **Agile нужен НЕ для создания продукта**, а для **управления командой**,
> которая продукт создаёт. Не путать.

### Модель 4 — Стадии создания продукта (6 стадий)

«Маршрут движения от идеи до лидерства на рынке»:

```
1. Discovery     2. Development   3. Piloting      4. Deployment    5. Scaling       6. Leading
   Исследования     Разработка      Пилотирование    Развертывание    Масштабирование   Лидерство
   ────────────    ────────────    ────────────    ────────────    ────────────    ────────────
   • Гипотезы      • Прототип      • Пилот          • Доработка     • Новые          • Макс. выручка
   • Исследования  • Тест           решения          решения          сегменты         / прибыли
   • Выбор идей    • MVP           • Пилот          • Product        • Доработка под  • Первые
                                    маркетинга и     Market Fit       сегменты         позиции
                                    продаж          • Маркетинг и    • Активные       • Устойчивая
                                   • Подтв.          продажи          продажи          компания
                                    ценности
```

Каждая стадия разбивается на этапы. Пример Discovery:

```
1. Гипотеза          2. Подготовка        3. Исследование      4. Кластеризация     5. Приоритизация
   ─────────            ─────────             ─────────             ─────────             ─────────
   о клиенте и          Карта                 JTBD-интервью         JTBD-                JTBD-
   задачах              стейкхолдеров         Наблюдение            сегментация          приоритизация
                        Экстремальные
                        пользователи
```

## Главные термины (часть глоссария)

| Термин | Смысл |
|--------|-------|
| **Проект** | Комплекс мероприятий с временными/ресурсными ограничениями (ГОСТ Р 54869-2011) |
| **Продукт** | Нечто (физическое/нет), созданное в проекте, дающее ценность рынку (Майк Кан) |
| **Фокус продакт-менеджера** | Продать X штук на рынке за Y рублей за период |
| **Фокус проект-менеджера** | Объём + сроки + бюджет + качество |
| **JTBD** | «Клиент нанимает продукт для решения своих задач» (см. [jtbd](jtbd.md)) |
| **MVP** | Minimum Viable Product |
| **PMF** | Product-Market Fit |
| **Пропасть Мура** | Разрыв между ранними последователями и массовым рынком |
| **Cynefin** | Фреймворк классификации задач по уровню сложности (см. [cynefin](cynefin.md)) |
| **OKR** | Objectives & Key Results |

## Как это ложится на 9-стадийный ЖЦ из vault'а

Моя локальная карта 9 стадий (см. [docs/playbooks/00-product-lifecycle](../docs/playbooks/00-product-lifecycle.md)) **детальнее**
чем 6 стадий Product Focus, потому что включает специфику российской
гос/корп разработки (ТЗ ГОСТ-19, КОСГУ-устав, НИР-отчёт).

Mapping и какие инструменты PF применять на каждой моей стадии — в
**[docs/playbooks/10-product-focus-mapping](../docs/playbooks/10-product-focus-mapping.md)**.

## Главное — что брать в работу

1. **4 фокуса** — фундаментальная рамка для discovery. Дополнить ими
   [discovery-interview skill](../knowledge/skills/discovery-interview.md):
   при опросе проверять, что Олег ответил на 4 ключевых вопроса
   (Клиент / Продукт / Бизнес / Тренды), а не только «Клиент».

2. **Пирамида структуры** — переиспользуема как способ описать
   собственную методологию проекта: что у нас Ценности (= политика
   в гос-проекте), Модели (= ADR), Методы (= плейбуки), Инструменты
   (= шаблоны).

3. **Стадии PF** — параллельная карта моим 9 стадиям, более гладкая
   для коммерческих b2c/b2b проектов.

4. **Фокусы управления** — у меня этого слоя в vault'е пока нет.
   Если соберусь работать с командой — добавлю плейбук про team focus.
