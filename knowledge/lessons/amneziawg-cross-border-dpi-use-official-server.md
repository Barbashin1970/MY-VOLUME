# Урок: «AmneziaWG через границу — только официальный сервер»

> Контекст: семейный VPN с немецким выходом из РФ (проект FREEWAY). Подняли
> VPS Hetzner, попытались поднять AmneziaWG-сервер своими руками. Промучились
> полдня. Вывод ниже сэкономит этот день в следующий раз.

## Что произошло

VPN «подключался», но интернета не было / «слабо работал». Симптом устойчивый и
обманчивый:
- Рукопожатие (handshake) проходит, статус «Подключено».
- Клиент **отправляет** килобайты, **получает** ~92 байта (только ответ
  рукопожатия). Сервер при этом шлёт десятки КиБ, но до клиента они не доходят.
- `ping` даже мелких пакетов (8.8.8.8 и тоннельного IP сервера) — 100% потерь.
- При этом «самотест» на самом сервере (клиент в network namespace → пинг
  8.8.8.8 через туннель) проходил на ура — что вводило в заблуждение.

## Почему это случилось

Три наложившихся причины (каждая по отдельности тоже стоила времени):

1. **Bleeding-edge ОС.** Сервер случайно подняли на Ubuntu 26.04 (ядро 7.0).
   AmneziaWG там не работает корректно: userspace `amneziawg-go` — флап
   рукопожатия; kernel-модуль — рукопожатие ок, но транспорт сервер→клиент
   теряется.
2. **Самосбор vs официальный клиент.** Сервер, собранный из исходников
   (kernel-модуль или `amneziawg-go` из master), **не интероперабелен с
   клиентом-приложением AmneziaWG**: рукопожатие común, а транспортные пакеты
   сервер→клиент клиент молча отвергает (нюансы обфускации/реализации). Тест
   «сервер↔сам себя» это НЕ ловит.
3. **Трансграничный DPI (ТСПУ).** Главное. Канал РФ→Германия фильтруется.
   Самодельная обфускация со случайными параметрами детектируется и душится:
   рукопожатие пропускают, поток данных режут почти в ноль. Старый московский
   сервер «работал» лишь потому, что трафик не пересекал границу — это сбивало
   с толку.

## Как починили

Снесли самосбор, поставили **официальный сервер через приложение AmneziaVPN**
(Self-hosted → Автоматическая → AmneziaWG) на Ubuntu **24.04 LTS**. Сразу
заработало: 2ip = Германия, реальный трафик пошёл. Официальный сервер — это
**AmneziaWG «версия 2»**: диапазоны H1–H4, S3/S4 и junk-пакет **`I1`,
маскирующий старт под DNS-запрос к icloud.com**, — именно он пробивает ТСПУ.

Панель (FREEWAY) затем не изобретает обфускацию, а берёт **точный шаблон
рабочего клиентского `.conf`** (снятый с сервера) и подставляет в него только
адрес и ключи клиента — ключи из панели идентичны официальным и проходят DPI.

## Чтобы не повторилось

- **Для VPN через границу РФ — ставь сервер официальным приложением Amnezia,
  не собирай руками.** Версия-в-версию с клиентом + обфускация, заточенная под
  ТСПУ. Самосбор оставь только для не-цензурируемых сценариев.
- **Под VPN — стабильная LTS-ОС (Ubuntu 24.04 / ядро 6.8), не свежак.** Bleeding
  edge ломает AmneziaWG.
- **Диагностируй по счётчикам с двух сторон** (`awg show` rx/tx на сервере и в
  клиенте). Асимметрия (одна сторона шлёт, другая получает ~0) мгновенно
  показывает направление обрыва. Подпись DPI: «рукопожатие есть, данные ~0».
- **Самотест на сервере (netns) НЕ доказывает работу для реального клиента** —
  он не ловит ни трансграничный DPI, ни несовместимость с клиентом-приложением.
- **Hetzner: создавай сервер сразу с SSH-ключом** (иначе ад со сменой
  «просроченного» root-пароля по SSH). При включённом туннеле `0.0.0.0/0` не
  диагностируй через SSH к самому VPN-серверу — рвётся; запускай автономный
  диагност через `systemd-run`.
