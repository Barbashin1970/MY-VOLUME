# Урок: «страховочная сетка, натянутая в пустоту»

> Контекст: РАГРАФ, редактор потока регламента
> (`frontend/src/components/flow/FlowEditorScreen.tsx`).

## Что произошло

В редакторе есть таймер: каждые 30 секунд текущий граф пишется в `localStorage`
под ключом `ragraf:flow-draft:<id>` (`FlowEditorScreen.tsx:113–122`, запись —
строка 116). Код стоит с первого коммита.

Читающего кода нет:

```bash
grep -rn "flow-draft" frontend/src
# FlowEditorScreen.tsx:116:    const key = `ragraf:flow-draft:${id}`   ← только запись
```

26.09.2026 владелец пожаловался: «после каждого деплоя настройки доставки
слетают». Разбор показал, что сохранения не было вовсе. Перезагрузка по баннеру
обновления уносила набранное, а черновик, который всё это время писался, никто
не предложил восстановить (`docs/NESOHRANENNOE-RAZBOR.md`).

## Почему это случилось

- **Запись и чтение — две половины одной функции, а сделана была одна.**
  Таймер выглядит как готовая защита, хотя без восстановления это просто
  растущий мусор в браузере.
- **Защиту не проверяли тем, от чего она защищает:** «набрал → перезагрузил →
  увидел предложение восстановить». Такой проверки нет, поэтому отсутствие
  чтения не всплыло ни разу за пять месяцев.

## Как починили

На 30.10.2026 — не починено. Против потери набранного сейчас работают другие
средства, введённые после жалобы 26.09: удержание `beforeunload` и полоса
«не сохранено» до пробы доставки (`dede440`). Автосохранение в историю отвергнуто
осознанно: оно засорит историю версий и отнимет шаг «я закончил» (`docs/BACKLOG.md`).
Мёртвая запись черновика заведена в бэклог: либо снять её, либо дописать
предложение «найден несохранённый черновик от … — восстановить?» с проверкой.

## Чем обнаружено

Чтением кода при подготовке главы о фронтенде для книги «Системный аналитик
в эпоху гибридного ИИ» (30.10.2026): поиск по ключу хранилища нашёл запись
без чтения.

## Чтобы не повторилось

- **Для каждого ключа хранилища ищи пару «запись ↔ чтение».** Поиск по ключу
  должен находить и `setItem`, и `getItem`. Одна сторона без другой — мёртвый
  код или незаконченная функция.
- **Защита от потери проверяется восстановлением,** а не фактом записи: «записал →
  перезапустил → восстановил».
- **В описании изделия называй только проверенное.** «Автосохранение черновика»,
  которое ничего не восстанавливает, — обещание, по которому пользователь
  перестаёт сохранять сам.
