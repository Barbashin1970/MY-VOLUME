# Стадия 5 — Архитектура (ARC.md)

**Вход:** ТЗ согласовано.
**Выход:** `ARC.md` (в `docs/` или в корне).
**Время:** 1-3 дня. Обновляется по мере роста, но **только осознанными
правками** — каждое крупное изменение → запись в `decisions.md`.
**Эталон:** `~/RAGRAF/docs/ARC.md`, `~/LEYKA/docs/ARC.md`, `~/GONKA/ARC.md`.

> ARC — главный технический документ. Его читает каждый, кто пришёл в
> проект: коллега, AI-ассистент, аудитор. Если ARC устарел, проект
> потерян.

## 18 секций ARC.md (структура RAGRAF)

| § | Раздел | Что внутри |
|---|--------|-----------|
| 1 | **Обзор** | Что система делает в одном абзаце + диаграмма high-level |
| 2 | **Слоистая архитектура** | Backend / Frontend / Storage / Deploy — таблица |
| 3 | **Author/Model/Execute split** | Если есть разделение «автор / модель / исполнитель» |
| 4 | **Доменная модель** | Mermaid `erDiagram` + поля 5-7 ключевых сущностей |
| 5 | **Жизненный цикл** | Mermaid `stateDiagram-v2` для главного объекта |
| 6 | **Rule DSL / Configuration model** | Если есть конфигурация / DSL |
| 7 | **ИИ-стек / external services** | LLM, RAG, embeddings, queue, …  |
| 8 | **Извлечение параметров / ETL** | Откуда данные приходят и как нормализуются |
| 9 | **Версионирование / снапшоты** | Как храним историю редактирований |
| 10 | **Хранилище** | DuckDB / SQLite / PostgreSQL — почему именно так |
| 11 | **API** | Список эндпоинтов с маршрутами и body-схемами |
| 12 | **Деплой** | Vercel + Railway / Fly / on-prem — что куда |
| 13 | **Метрики и мониторинг** | Что измеряется, где смотрится |
| 14 | **Тестирование** | Стратегия (unit / contract / e2e) + кол-во тестов |
| 15 | **ADR — Architecture Decision Records** | Список локальных решений |
| 16 | **Развитие** | Что в roadmap'е, что в антискоупе |
| 17 | **UI-фичи** | Список ключевых экранов |
| 18 | **Ссылки** | На TZ, на playbook'и, на код |

Можно сокращать до 10-12 секций для простых проектов. Игры (GONKA)
обходятся 8-10 разделами: game-loop, state-machine, AI-bots, network.

## Принципы написания ARC.md

### 1. Помещается на одну страницу — кратко-в-каждой-секции

Если ARC > 1000 строк — это уже архитектурная **книга**, выноси её в
`docs/architecture/<system>/`. ARC.md должен прочитаться за 20 минут.

### 2. Каждое решение обоснованo

> «SQLite (а не PostgreSQL) — потому что < 100 пользователей,
> backup как файл, миграция позже без боли через `DATABASE_URL`».
> *(LEYKA/docs/ARC.md)*

Если решение спорное — оно становится ADR в `decisions.md`.

### 3. Диаграммы — Mermaid, в самих секциях

Не выноси все диаграммы в `assets/` — пусть живут в md. Mermaid GitHub
рендерит нативно.

### 4. Не дублирует ТЗ и README

ARC говорит **как**. ТЗ — **что и почему**. README — **зачем
пользователю**.

### 5. Backend и frontend — раздельные разделы

Не смешивай. У LEYKA есть отдельные `CLAUDE.md` и `CLAUDE-FRONTEND.md`
с детальными конвенциями фронта — это правильно.

## Что должно быть в каждой ключевой секции

### §1 Обзор — формула

```markdown
## 1. Обзор

<Продукт> — это <класс системы> для <целевого пользователя>,
выполняющий <главную задачу>. Технологически — <стек 3-5 слов>.

```mermaid
flowchart LR
    A[Источники] --> B[<Продукт>] --> C[Потребители]
```
```

### §4 Доменная модель — Mermaid + Python-классы

Mermaid `erDiagram` для связей + сразу под ним — Python/TS-классы
с типами полей (как в LEYKA STARTING-A-PROJECT.md §4.1).

## Когда ARC.md обновляется

| Событие | Действие |
|---------|----------|
| Новый эндпоинт | Обнови §11 |
| Новая сущность в БД | Обнови §4 + миграция в коде |
| Сменили БД | Обнови §10 + ADR-NNN |
| Новый внешний сервис | Обнови §7 |
| Новая UI-страница | Обнови §17 |
| Любое крупное решение | Запись в `decisions.md` + ссылка из §15 |

## Antipatterns ARC.md

❌ **«Будущее в ARC».** Не описывай roadmap внутри §1-14. Только текущее
   состояние. Roadmap — в §16.

❌ **Дублирование TЗ.** ARC говорит «как». Требования — в ТЗ.

❌ **Скриншоты UI.** UI меняется, документ застывает. Описывай
   маршрутом / именем экрана.

❌ **ASCII-псевдографика `┌─┐│`.** Mermaid. Без исключений.

❌ **«Living TODO» прямо в ARC.** TODO → BACKLOG.md.
