# Граф знаний

Это **единое локальное хранилище заметок** для:

- **Obsidian** — повседневная работа, граф связей через `[[wikilinks]]`.
- **GitHub Pages** — публикация выбранных разделов в публичную/командную базу.
- **Claude Code** — контекст для AI-ассистента: «прочитай vault и ответь».
- **Команды/коллег** — единая точка правды, куда новый человек заходит и понимает, что происходит.

> **Главная цель:** опыт каждого следующего проекта обогащает [[knowledge]] и
> [[docs/decisions]], а не теряется на дне диска. Баг, найденный в `LEYKA`,
> должен помочь не наступить на него в `RAGRAF` и в следующем проекте N+1.

---

## Как ориентироваться

Начни с карты содержимого: [MOC.md](MOC.md) — это «оглавление» vault'а.

| Папка | Что внутри | Когда писать сюда |
|-------|-----------|-------------------|
| [projects/](projects/) | Активные и архивные проекты | Всё, что специфично одному репозиторию |
| [knowledge/](knowledge/) | Переиспользуемое знание: языки, стеки, паттерны, skills, tools, lessons | Когда понял что-то общее: «так делают везде» |
| [docs/](docs/) | Полированные документы под публикацию | Архитектура, ADR-решения, playbook'и |
| [concepts/](concepts/) | Атомарные понятия / глоссарий | Один термин = одна заметка |
| [people/](people/) | Карточки людей: коллеги, клиенты, контрагенты | Только то, что помогает работать |
| [meetings/](meetings/) | Заметки со встреч | По одной заметке на встречу |
| [inbox/](inbox/) | Быстрый сброс мыслей до сортировки | Когда некогда думать, куда положить |
| [templates/](templates/) | Шаблоны для новых заметок | Не редактируй вручную — копируй |
| [assets/](assets/) | Картинки, PDF, прочие бинарники | Не клади md-файлы сюда |

В каждой папке лежит свой `README.md` — мини-инструкция, как правильно её
наполнять. **Прочитай их хотя бы раз** перед первой записью.

## Соглашения, обязательные везде

1. **Имена файлов** — английский kebab-case: `fastapi-async-patterns.md`, не
   `FastAPI Async Patterns.md`. Это даёт корректные URL для GitHub Pages,
   стабильные ссылки в Obsidian и предсказуемые пути для Claude Code.

2. **YAML frontmatter** — в начале каждой заметки. Минимум:
   ```yaml
   ---
   title: Человеко-читаемое название
   tags: [stack/fastapi, lang/python]
   created: 2026-05-26
   updated: 2026-05-26
   ---
   ```
   Frontmatter читают и Obsidian (поиск, dataview), и Jekyll/GH Pages, и
   Claude Code (как структурированный контекст).

3. **Ссылки** — `[Заголовок](relative/path.md)` (работает в Obsidian, GitHub
   и GH Pages). Wikilinks `[[name]]` тоже допустимы внутри Obsidian, но
   при публикации они могут не отрендериться — поэтому **в `docs/` пиши
   только markdown-ссылки**.

4. **Один файл — одна идея.** Atomic notes. Если в заметке два независимых
   понятия — раздели на две и свяжи ссылками. Это даёт работающий граф.

5. **Никогда не дублируй контент** — лучше сослаться. Source of truth должен
   быть один. Если в `projects/leyka/` и в `knowledge/stacks/fastapi.md`
   написано одно и то же — это баг.

6. **Даты — абсолютные** (`2026-05-26`), не «вчера» / «на прошлой неделе».

7. **Язык** — русский для содержимого, английский для имён файлов, тегов и
   ключей frontmatter.

## Поток знаний (главный принцип)

```
        Новый проект
             │
             ▼
   projects/active/<name>/
   ────────────────────────
   • README.md      — что и зачем
   • arc.md         — архитектура
   • backlog.md     — что делать
   • bugs.md        — что сломалось и как починили
   • decisions.md   — почему именно так
             │
   На каждом ретро / по завершении этапа:
             │
             ▼
   ─── вытащить переиспользуемое ───
             │
             ├──► knowledge/lessons/   ← урок, который применим везде
             ├──► knowledge/skills/    ← рецепт ≈ SKILL-XX.md
             ├──► knowledge/patterns/  ← архитектурный приём
             ├──► concepts/            ← новый термин в глоссарий
             └──► docs/decisions/      ← ADR — если решение системное
             │
   В следующем проекте:
             │
             ▼
   Claude Code читает knowledge/ → не повторяешь старых ошибок.
```

**Правило большого пальца:** если ты что-то узнал и думаешь «это мне ещё
пригодится в другом проекте» — это знак вытащить заметку из `projects/`
вверх, в `knowledge/` или `concepts/`.

## Если хочется опубликовать через GitHub Pages

1. `git init && git remote add origin <repo>`.
2. Положить в корень `_config.yml` с темой `just-the-docs` или `minimal`.
3. Папки `assets/`, `templates/`, `inbox/` исключить через `exclude:` в
   `_config.yml`.
4. Раздел `docs/` — основная публичная часть. Остальные папки можно
   публиковать выборочно.
