# CLAUDE.md — для AI-ассистента

Этот файл — **системный контекст** для Claude Code, когда он работает с
этим vault'ом. Если ты Claude — прочитай его до того, как давать ответы.

---

## Что это за хранилище

Личный граф знаний Олега. **Не репозиторий с кодом** — здесь только md-файлы
с инженерным и продуктовым опытом. Код проектов лежит в `~/<PROJECT>/`
(`~/LEYKA`, `~/GONKA`, `~/RAGRAF`, …). Сюда вытаскивается **обобщённое
знание**, которое должно пережить отдельный проект.

---

## Главное правило поиска ответа

Когда тебя просят «как сделать X», читай в таком порядке:

1. **[knowledge/lessons/](knowledge/lessons/)** — может, мы это уже сломали и
   починили. Не повторяй ошибок.
2. **[knowledge/skills/](knowledge/skills/)** — есть ли готовый рецепт.
3. **[knowledge/patterns/](knowledge/patterns/)** — есть ли архитектурный
   приём, который сюда ложится.
4. **[docs/decisions/](docs/decisions/)** — есть ли принятое решение, которое
   ограничивает выбор.
5. **[projects/active/](projects/active/)** — как мы делали это раньше.
6. **[concepts/](concepts/)** — корректно ли я понял термины.

Только потом — общая эрудиция.

---

## Когда обновлять vault — без явной просьбы

В конце задачи спрашивай себя: «что из проделанного применимо в следующем
проекте?». Если ответ «да» — **предложи** (не делай молча) сохранить заметку:

- Нашли неожиданный баг и починили → [knowledge/lessons/](knowledge/lessons/).
- Применили нестандартный паттерн, который сработал → [knowledge/patterns/](knowledge/patterns/).
- Узнали трюк со стеком/тулом → [knowledge/skills/](knowledge/skills/) или
  [knowledge/tools/](knowledge/tools/).
- Приняли важное решение «делаем так, потому что …» → [docs/decisions/](docs/decisions/).
- Появился новый термин → [concepts/](concepts/).

**Никогда не пиши в `docs/` без явной просьбы** — это публикуемый раздел.

---

## Соглашения, которые нельзя нарушать

1. Имена файлов — английский kebab-case.
2. Frontmatter обязателен (см. [templates/](templates/)).
3. Один файл — одна идея.
4. Ссылки через `[Текст](relative/path.md)`, без `[[wikilinks]]` в `docs/`.
5. Даты — абсолютные ISO (`2026-05-26`).
6. Не дублируй контент — ссылайся.

---

## Если что-то противоречит — как разрешать

| Конфликт | Что побеждает |
|----------|---------------|
| `projects/<x>/decisions.md` vs `docs/decisions/` | `docs/decisions/` — более актуально, оно курировано |
| Старая запись vs свежая `git log` / код | Код. Старую запись пометь «устаревшее» или обнови |
| Frontmatter vs тело заметки | Тело. Frontmatter — индекс, не источник |
| Заметка в `inbox/` vs где-либо ещё | Любая отсортированная заметка. `inbox/` — черновики |

---

## Что **не** делать

- Не создавай новых корневых папок без обсуждения. Структура зафиксирована.
- Не клади бинарники куда-либо, кроме `assets/`.
- Не пиши заметки длиннее 300 строк — разбей на две и свяжи.
- Не пиши «TODO: дописать позже» в `docs/` — это уже опубликовано.
- Не дублируй то, что есть в `~/.claude/.../memory/` — это память для тебя,
  здесь — знание для людей и для будущих сессий.

## Краткий обзор папок

| Папка | Доминирующий жанр заметок |
|-------|---------------------------|
| `projects/` | Жизнь конкретного репозитория: README, ARC, backlog, bugs, decisions |
| `knowledge/` | Что я знаю про языки/стеки/паттерны/инструменты и какие уроки извлёк |
| `docs/` | Опубликованные документы — архитектура, ADR, playbook'и |
| `concepts/` | Атомарные понятия — глоссарий, разрастающийся в граф |
| `people/` | Карточки людей |
| `meetings/` | Журнал встреч |
| `inbox/` | Черновики, ждущие сортировки |
| `templates/` | Шаблоны для копирования |
| `assets/` | Картинки и PDF |
