# Урок: снимок с телефона — EXIF и папка public/

## Что произошло

28.10.2026. Для раздела «Контакт» сайта-портфолио Олег прислал своё фото и положил его
в `public/IMG_0131.JPG` — рядом с медиа сайта. Сайт открытый, его репозиторий тоже,
история git хранится вечно.

| Что проверили | Чем | Результат |
|---|---|---|
| Где лежит снимок | `find … -iname 'IMG_0131*'` | две одинаковые копии (`cmp`): в «Загрузках» и в `public/` |
| Видит ли его git | `git status --short`, `git check-ignore -v` | `?? public/IMG_0131.JPG`, в `.gitignore` не входит |
| Размер и профиль | `sips -g pixelWidth -g pixelHeight -g profile` | 720×1280, sRGB, 92 192 байта |
| Метаданные | метка `Exif` в начале файла | блок EXIF есть |
| Место съёмки | `mdls -raw -name kMDItemLatitude` (и `Longitude`) | `(null)` — координат нет |

Утечки не случилось: снимок не был закоммичен, а координат в нём не оказалось. Но до
неё оставался один `git add public/`.

## Почему это случилось

- **`public/` выглядит как «папка для картинок сайта», а для сборщика это «скопировать
  на сайт как есть».** Vite кладёт её содержимое в собранный сайт без обработки и под
  тем же именем, вместе с метаданными. Положить туда исходник — значит опубликовать его
  при ближайшей сборке, если файл попадёт в git.
- **Снимок с телефона — не только картинка.** В EXIF лежат модель телефона, время съёмки
  и координаты, если камере разрешена геолокация. Ни в превью, ни глазом этого не видно.
- **Пережатый снимок кажется чистым.** Здесь он был всего 720×1280, а блок EXIF
  в нём всё равно остался.

## Как починили

- **Исходник вынесли из `public/` в `.private/`.** Эта папка в `.gitignore`, только
  на ноутбуке. Копия в «Загрузках» осталась у владельца.
- **На сайт пошли производные файлы с явным снятием метаданных:**

  ```
  ffmpeg -i <снимок>.JPG -vf "crop=720:1040:0:0" -map_metadata -1 -c:v libwebp -quality 80 -compression_level 6 public/media/oleg.webp
  ffmpeg -i <снимок>.JPG -vf "crop=460:460:165:80,scale=132:132:flags=lanczos" -map_metadata -1 -c:v libwebp -quality 82 -compression_level 6 public/media/oleg-avatar.webp
  ```

  Портрет вышел 55 492 байта, кружок для шапки чата — 3 104.
- **Проверен готовый файл, а не команда.** У обоих WebP в контейнере RIFF один блок —
  `VP8 `, без `EXIF` и `XMP `. У скриншотов, снятых Chrome, есть блок `ICCP` — это
  цветовой профиль, а не данные съёмки; его оставили.
- **Тест-сторож по всем медиа сайта** — `tests/media.test.ts` в открытом репозитории
  https://github.com/Barbashin1970/portfolio, коммит `68dc074`:
  - в каждом WebP нет блоков `EXIF` и `XMP `;
  - контроль разбора: в каждом файле найден блок кадра `VP8*`, иначе «EXIF нет» ничего
    не значит;
  - в каждом MP4 нет атома места QuickTime — `©xyz` и `com.apple.quicktime.location`;
  - подложенный WebP с дописанным блоком `EXIF` роняет тест: `expected [ 'VP8 ', 'EXIF' ]
    to not include 'EXIF'`.
- **Заодно проверены шесть роликов, которые уже были на сайте.** Ни места съёмки, ни модели
  устройства в них нет.

## Чтобы не повторилось

- **Снимок от человека — исходник, а не медиа сайта.** Он лежит вне `public/` и вне git
  (`.private/` или вне проекта); на сайт идёт только производный файл.
- **Проверять исходник, не раскрывая данных.** `mdls -raw -name kMDItemLatitude <файл>`
  на macOS, `exiftool -gps:all <файл>` где он есть. В отчёт и в переписку — только «есть
  координаты или нет», без самих чисел.
- **Метаданные снимать явно при конвертации.** `ffmpeg … -map_metadata -1`, для JPEG —
  `exiftool -all= <файл>`. Затем проверить готовый файл:
  - WebP — список блоков RIFF;
  - JPEG — сегмент APP1 с меткой `Exif`;
  - MP4 — атомы `©xyz` и `com.apple.quicktime.location`.
- **Сторож — тест по всем медиа репозитория,** а не разовая проверка одного файла.
  У теста два контроля: разбор видит кадр, и подложенный файл с метаданными тест роняет.
- **Новый файл в `public/` — повод остановиться.** Перед коммитом — `git status --short`,
  файлы добавлять поимённо, без `git add .`.
- **HEIC на сайт не идёт:** Chrome и Firefox его не показывают, его всё равно
  конвертировать — заодно и без метаданных.
