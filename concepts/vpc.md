# VPC — Value Proposition Canvas

**Двухсторонний канвас Александра Остервальдера** (соавтор Business
Model Canvas). Слева — карта ценности продукта, справа — профиль
потребителя. Их **fit** (совпадение) — главный артефакт.

> Если левая и правая половины не совпадают — мы делаем не то, что
> нужно клиенту.

## Структура

```
┌──────────────────────────┐         ┌──────────────────────────┐
│   КАРТА ЦЕННОСТИ         │         │   ПРОФИЛЬ ПОТРЕБИТЕЛЯ   │
│                          │         │                          │
│  ┌──────────────────┐    │         │  ┌──────────────────┐    │
│  │ Продукты/услуги │    │ ←FIT→  │  │ Задачи клиента  │    │
│  └──────────────────┘    │         │  └──────────────────┘    │
│  ┌──────────────────┐    │         │  ┌──────────────────┐    │
│  │ Pain relievers  │    │ ←FIT→  │  │ Боли (pains)    │    │
│  └──────────────────┘    │         │  └──────────────────┘    │
│  ┌──────────────────┐    │         │  ┌──────────────────┐    │
│  │ Gain creators   │    │ ←FIT→  │  │ Выгоды (gains)  │    │
│  └──────────────────┘    │         │  └──────────────────┘    │
└──────────────────────────┘         └──────────────────────────┘
```

### Профиль потребителя (правая часть)

| Блок | Что внутри |
|------|-----------|
| **Customer Jobs** — задачи клиента | Что клиент пытается выполнить (см. [jtbd](jtbd.md)). Функциональные / эмоциональные / социальные. |
| **Pains** — боли | Что мешает, раздражает, тормозит, страшит. С метриками («теряю 2 часа в день»). |
| **Gains** — выгоды | Что хочется получить сверх минимума. Ожидаемые / желаемые / неожиданные. |

### Карта ценности (левая часть)

| Блок | Что внутри |
|------|-----------|
| **Products & Services** | Конкретный список того, что продаём (фичи, услуги). |
| **Pain Relievers** | Как наш продукт **убирает** боли клиента. Каждая связана с конкретной болью справа. |
| **Gain Creators** | Как наш продукт **создаёт** выгоды. Каждая связана с конкретной выгодой справа. |

## Главный критерий — Product-Market Fit

> **Каждый pain reliever** должен закрывать **конкретную** pain справа.
> **Каждый gain creator** — конкретную gain.

Если на карте ценности есть фича без связи с профилем — это **технический долг бизнеса**. Возможно, она не нужна.

## VPC vs Lean Canvas vs JTBD

| Инструмент | Что покрывает |
|-----------|---------------|
| **JTBD** | Только сторона клиента — какую работу нанимают делать |
| **VPC** | Сторона клиента + сторона ценности продукта, **fit между ними** |
| **Lean Canvas** | Бизнес-модель целиком (доходы, затраты, каналы), без глубины по клиенту |

**Порядок применения:** JTBD → VPC → Lean Canvas. JTBD даёт сырьё для
правой стороны VPC. VPC даёт сырьё для блоков 1-4 Lean Canvas.

## Применение в твоих проектах

| Проект | VPC-набросок |
|--------|--------------|
| **SOFIA** | Jobs: «понять себя», «получить инструмент работы с эмоциями». Pains: «эзотерика звучит несерьёзно», «не знаю с чего начать». Gain creators: «научный фрейм Юнга + нумерология», «персональный рецепт» |
| **RAGRAF** | Jobs: «не пропустить нарушение регламента». Pains: «ручная проверка занимает дни», «нет связи между датчиками и задачами». Pain relievers: автоматическая задача в LEYKA |
| **LEYKA** | Jobs: «закрыть отчётный год без аврала». Pains: «декабрь = неделя ручной сводки КОСГУ». Pain relievers: автокатегоризация задач по КОСГУ при закрытии |

## Когда VPC избыточен

- **Демо-проект** (категория D) — JTBD достаточно.
- **Pet-проект** (B) — продукт делается для себя, fit очевиден.
- **Готовое ТЗ от заказчика** (B2G) — fit зафиксирован контрактом.
