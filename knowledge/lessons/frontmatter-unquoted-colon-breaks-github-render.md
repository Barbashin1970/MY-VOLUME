# Урок: «двоеточие в заголовке сломало заметку на GitHub»

> Контекст: 2026-11-03, [отчёт о сервере языковых моделей для НГУ](../tools/llm-server-2x-rtx5090-report-2026-11-03.md)
> закоммичен (`2e9c524`) и отправлен на GitHub.

## Что произошло

На странице отчёта в GitHub вместо таблицы свойств заметки — ошибка:

```text
Error in user YAML: (<unknown>): mapping values are not allowed in this context at line 1 column 64
```

Строка 1 frontmatter — `title`, позиция 64 — двоеточие в «…для НГУ: проверка конфигурации…». Сам
markdown-текст файла цел, ломается разбор шапки — и вместе с ней всё, что читает заметку по полям.

Проверка всех заметок vault тем же парсером (команда — в заметке
[git-hooks-pre-commit](../tools/git-hooks-pre-commit.md), раздел «Проверить весь vault»), 2026-11-03,
до правки:

| Сколько | Что |
|---|---|
| 191 | заметка с frontmatter |
| 9 | не разбираются |
| 7 из 9 | двоеточие с пробелом в `description` без кавычек |
| 1 из 9 | двоеточие с пробелом в `title` без кавычек — этот отчёт |
| 1 из 9 | `title` начинается с обратной кавычки `` ` `` |

## Почему это случилось

- В YAML значение без кавычек не может содержать «: » — двоеточие с пробелом парсер считает началом
  новой пары «ключ: значение»: `mapping values are not allowed in this context`. Двоеточие без пробела
  (`12:30`, `https://…`) допустимо, поэтому ошибка выглядит случайной.
- Значение без кавычек не может и начинаться со служебного символа YAML — обратной кавычки, `@`, `*`,
  `&`, `!`, `|`, `>`, `%`, `#`, `[`, `{`, кавычек: `found character that cannot start any token`.
  Обратная кавычка в начале — частый случай, когда заголовок начинается с команды или флага.
- Русский текст пояснения пишет через двоеточие («по трём причинам: …»), а `description` в vault —
  несколько предложений. Чем длиннее значение без кавычек, тем вероятнее в нём «: ».
- Привычка была половинчатой: `description` в новых заметках брался в кавычки, `title` — нет.
  Шаблон [templates/lesson.md](../../templates/lesson.md) тоже даёт оба поля без кавычек.
- До push ошибку ничто не показало: проверки frontmatter перед коммитом не было.

## Как починили

- Значение `title` отчёта взято в двойные кавычки — правка одной строки, коммит `9c600f2`:

  ```diff
  -title: Отчёт — сервер языковых моделей на двух RTX 5090 для НГУ: проверка конфигурации, …
  +title: "Отчёт — сервер языковых моделей на двух RTX 5090 для НГУ: проверка конфигурации, …"
  ```

- Проверено тем же парсером: локальный Psych (Ruby 2.6.10) до правки выдал строку ошибки GitHub
  дословно, после — разобрал шапку, `title` прочитан целиком, все шесть полей на месте.
- Поставлен сторож — pre-commit-хук [git-hooks-pre-commit](../tools/git-hooks-pre-commit.md); проверен на
  временном репозитории: двоеточие в `title`, обратная кавычка, ошибка в индексе при исправленной рабочей
  копии и `commit -a` останавливают коммит, значение в кавычках проходит.
- Остальные 8 заметок на момент записи урока не исправлены; список выдаёт команда проверки всего vault.

## Чем обнаружено

Владелец открыл отчёт на GitHub после push. Масштаб показала проверка всего vault тем же парсером: одна
ошибка оказалась девятой из 191.

## Чтобы не повторилось

- **`title` и `description` — всегда в двойных кавычках.** Тогда не нужно помнить, какие символы
  опасны. Внутри двойных кавычек экранируются только `"` и `\`; для цитат внутри значения — «ёлочки».
- **Сторож перед коммитом.** Хук разбирает frontmatter каждой коммитируемой заметки и останавливает
  коммит с адресом `файл:строка:позиция`. `.git/hooks/` не клонируется: на новой машине хук ставится
  одной командой из заметки [git-hooks-pre-commit](../tools/git-hooks-pre-commit.md).
- **Не обходить сторожа** через `git commit --no-verify` — чинить причину
  ([плейбук качества](../../docs/playbooks/13-quality-management.md)).
- **Проверять тем парсером, который будет читать.** Здесь читатель — GitHub; локальный Psych дал его
  строку ошибки дословно, значит, проверка видит то же, что увидит читатель.
- **Шапка — тоже утверждение документа о себе.** Она обещает «у заметки есть заголовок и метки», и это
  обещание проверяется машиной, как числа ([document-promise-needs-a-guard](document-promise-needs-a-guard.md)).
