# Урок: «новый файл выключил старый псевдоним»

> Контекст: РАГРАФ, Студия аналитика. Факты базы знаний (тройки) подбираются
> к ответу по области вопроса. Карта «область → файлы данных» собирается из
> нескольких источников: старый список, манифест, домены регламентов, привязки
> пользователя и с 09.11.2026 — файлы мостов.

## Что произошло

Резолвер области устроен так:

```python
def _resolve(domain_id):
    key = _norm(domain_id)
    if key in cache:                  # свой ключ есть — псевдоним не нужен
        return cache[key]
    alias = _DOMAIN_ALIASES.get(key)  # heating → heating-network,
    if alias and alias in cache:      # urban-transport → traffic-monitoring
        return cache[alias]
```

09.11.2026 появились файлы мостов, по одному на область регламентов. Имя файла
стало ключом области: `mosty/heating.csv` → ключ `heating`. У `heating` и
`urban-transport` своего ключа до этого не было, их направлял псевдоним. Теперь
ключ появился, и резолвер перестал доходить до псевдонима:

- в блок ответа Студии по теплоснабжению шли 4 строки, и все они были мостами;
- 49 фактов о тепломагистрали и 55 о дорожном движении до ответа не доходили;
- выжимка для маршрутизатора областей собиралась из мостов: «понятия:
  Регламент_pressure_diameter, …» вместо «Тепломагистраль, Тепловые сети, …».

Ошибок не было нигде: код 200, блок не пустой, все проверки зелёные.

## Почему это случилось

**Псевдоним включался отсутствием, а не правилом.** «Иди к псевдониму, если
своего ключа нет» верно, только пока под ключом области не появится никаких
данных. Любой новый источник с этим ключом тихо выключает псевдоним целиком.
Источник при этом может быть каким угодно — даже вспомогательным, как мосты.

**Сторож смотрел другие области.** Проверка блока троек держала три области
со своими датасетами. Ни одна из двух областей с псевдонимом в неё не входила.

**Пустоты не было, поэтому никто ничего не заметил.** Блок не опустел: мосты
его заполнили. Ответ выглядел осмысленным, просто беднее.

## Как починили

12.11.2026: при сборке карты файлы псевдонима добавляются к своим файлам
области (`backend/app/services/domain_knowledge.py`, конец `_domain_files`).
Сторож `test_psevdonim_ne_zatenen_mostami` проверяет каждую пару из словаря
псевдонимов:

- у области есть свои мосты, то есть случай как раз тот;
- файлы псевдонима входят в файлы области;
- в блоке ответа и в выжимке маршрутизатора есть слово из фактов псевдонима.

Сторож видели красным на коде до починки — по обеим областям.

## Чтобы не повторилось

- **Псевдоним сливать, а не подменять.** Если у области может появиться свой
  источник, пусть псевдоним добавляет свои данные к её данным, а не включается
  только при их отсутствии.
- **Сторож ставить на каждый псевдоним, а не на выборку областей.** Обход
  словаря псевдонимов, а не перечень «важных» областей: перечень не растёт
  вместе с данными (см. урок про охват сторожа).
- **Новый источник данных под существующим ключом — повод пересмотреть
  резолвер.** При добавлении файлов «по одному на область» проверить, не
  совпадает ли имя с ключом, у которого есть особое поведение.
- **«Блок не пустой» — слабая проверка.** Сверять, что в выдаче есть данные
  конкретного источника, а не что выдача есть.
