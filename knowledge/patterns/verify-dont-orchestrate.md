# Pattern: Verify, Don't Orchestrate

Внешний rule/regulation-движок (РАГРАФ, d0sl) **не должен стоять в пути быстрой реакции/оркестрации**
— только в пути **пост-фактум проверки и доказательства**. Выведено из кейса Олега (Redmine + d0sl,
публикация игр в Игросферу) + анализа Яндекс Трекера, 2026-07-17.

## Проблема

Соблазн: раз есть мощный движок правил (Flow DSL / d0sl), прогонять через него ВСЁ — включая
оркестрацию задач (перевести статус, назначить тестировщика, проверить, что файл залит, дать
публикацию). Но внешний движок работает по модели «постучись → проверь статусы/файл» — асинхронно,
с задержкой и внешней зависимостью. Для оркестрации это **хуже**, чем встроенная синхронная
автоматизация трекера.

## Кейс (откуда выведено)

Публикация Android-игр: разработчик регистрирует заявку в **Redmine** → публикация в маркетплейс
**Игросфера** (типа Google Play) → постановка задач тестировщикам. Олег рассматривал d0sl-регламент,
но встроенная **Ruby-автоматизация Redmine работала чётко и синхронно** — без ожидания, пока
d0sl «постучится и проверит статусы и заливку файла».

## Решение (граница)

- **Оркестрация** — синхронные in-domain переходы (статус, назначение, gate по наличию файла) →
  **встроенная автоматизация трекера** (Redmine Ruby / Jira Automation / Яндекс «Автоматизация»).
  Мгновенно, без внешней зависимости.
- **Верификация/доказательство** — корректно ли само правило; выполнено ли условие ПО СУЩЕСТВУ;
  K3 «нет данных»≠ложь; неизменяемый версионируемый реестр несоответствий; трасса PROV-O для аудита →
  **внешний rule-движок**. Асинхронность тут НЕ минус: продукт — аудиторский артефакт, а не реакция
  в реальном времени.
- Правило: **отдай оркестрацию их движку, возьми только слой проверяемости.** Это и неконкурентно
  (не покушаешься на то, что их автоматизация делает хорошо), и честно.

## Тест-на-границу (быстрый)

Если ценность действия — **скорость реакции** → встроенная автоматизация. Если ценность —
**доказательство постфактум** (аудит/инцидент/комплаенс) → внешний движок. Латентность внешнего
движка приемлема ровно потому, что доказательство смотрят на разборе, а не в реальном времени.

## Применения

- **RAGRAF × Яндекс Трекер** (2026-07): позиционирование питча — оркестрацию отдаём «Автоматизации»,
  РАГРАФ = только слой проверяемости. `~/RAGRAF/docs/RESEARCH-YANDEX-TRACKER-VALUE-2026-07.md` §6.1.
- **Redmine + d0sl** (публикация игр, Игросфера) — где встроенная Ruby-автоматизация выиграла у
  внешнего регламента для оркестрации (первичное наблюдение).
