# Урок: «открыли репозиторий — открыли и то, что в нём прятали»

> Контекст: курс «ИИ в учебном процессе» (`~/PROMPT-Professor`). Репозиторий на GitHub был
> приватным, наружу публиковался только сайт (`site/` через Vercel). 06.10.2026 автор сменил
> видимость на публичную — образец для учителей, которые строят свой курс.

## Что произошло

В публичном репозитории по прямой ссылке (`raw.githubusercontent.com/…`, ответ 200) открывались:

- `vhod/niokr-ne-publikovat/` — отчёт о НИР и ТЗ с непубличной тематикой. Тем же утром их
  убрали из навыка на сайте — **перенесли в папку «не публиковать» внутри репозитория**
  и закоммитили;
- те же файлы в истории — в старом месте, в коммитах до переноса;
- `docs/TEST-ZACHET-…` — вопросы зачёта с верными ответами.

Решение «открыть» принималось ради сайта и кода, о содержимом `docs/` и `vhod/` в тот момент
не думали.

## Почему это случилось

**«Не публиковать» значило «не на сайт», а не «не в репозиторий».** Сайт защищали
`.vercelignore` и папка вывода; репозиторий считался закрытым навсегда. Смена видимости
отменила второе условие, а папки остались.

**`.gitignore` действует только на новые файлы.** Отслеживаемое он не снимает с учёта и из
истории не убирает. Нужны `git rm --cached` и чистка истории.

**История публична так же, как дерево.** Любой старый коммит открывается по ссылке, пока
его не вычистили (`git filter-repo`) и не перезаписали ветку.

## Как починили

1. `vhod/` — в `.gitignore` и `git rm -r --cached vhod` (локальные файлы на месте).
2. Порядок для автора: закрыть репозиторий → закоммитить снятие с учёта → в **свежей копии**
   `git filter-repo --invert-paths --path vhod/ --path <старые пути>` → `git push --force` →
   в рабочей копии `git fetch && git reset --hard origin/main` → открыть снова.
   Чистка в отдельной копии — потому что в рабочей могут быть незакоммиченные правки
   (так и было в соседнем пакете навыков).

## Чтобы не повторилось

**Правило 1. Перед сменой видимости — опись.** `git ls-files` по папкам и
`git log --all --oneline -- <путь>` по всему, что когда-то называлось «не публиковать»,
«черновик», ключами, ответами, договорами.

**Правило 2. Непубличное держать вне репозитория с первого дня**, а не в папке с пометкой:
папка в `.gitignore` переживёт любую смену видимости.

**Правило 3. Убирать — в порядке «закрыть → снять с учёта → вычистить историю → открыть».**
Новый коммит с удалением ничего не скрывает.

**Правило 4. Есть ли форки и копии — проверить сразу:** `forks_count` в API GitHub. Форк
чужой — его не вычистить.

**Проверка.** `curl -s -o /dev/null -w "%{http_code}" https://raw.githubusercontent.com/<ник>/<repo>/main/<путь>` —
404 для всего непубличного; `git log --all -- <путь>` — пусто.
