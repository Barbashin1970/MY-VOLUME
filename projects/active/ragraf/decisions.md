# RAGRAF — локальные решения

---

## 2026-05-13 — Phase 1+2 закрытия задачного подхода

**Контекст.** К 2026-05-13 закрыто 4 из 10 узлов методологии Гончарова-Свириденко
+ ТФС Анохина (4 компонента задачи + 6 стадий). Остальные 6 — «частично»
или «нет».

**Решение.** Закрыть синхронную (Phase 1) + гибридную (Phase 2) половину
критерия решённости + подкрепление. Это поднимает счёт до 8/10.

**Альтернативы:** идти сразу на 10/10 (СВЗ вывод + Σ-определимость) —
слишком много за один заход.

**Результат:** реализовано к 2026-05-23. См. STRATEGY-POSITIONING §2.3.

## 2026-05-21 — Mermaid only, ASCII-псевдографика запрещена

**Контекст.** Стандартизация диаграмм во всех документах ГОСТ-19.

**Решение.** Только Mermaid (`flowchart`, `stateDiagram-v2`, `erDiagram`,
`sequenceDiagram`). GitHub и большинство IDE рендерят нативно.

**Альтернативы:** ASCII (`┌─┐│`) — отвергнуто: плохо на мобильных,
не масштабируется.

См. SKILL-GOST-19.md §4.4.

## 2026-05-15 — Single-user prototype, multi-user отложен

**Контекст.** TZ §4.3 описывает три роли (Аналитик-методолог, Диспетчер,
Руководитель), но реализуется только Аналитик-методолог.

**Решение.** Single-user до пилота. Multi-user / RBAC / SSO — после
первого боевого внедрения, в платформенном контуре Σ Сигма.

**Альтернативы:** RBAC сразу — переусложнило бы прототип.

См. TZ_RAGRAF.md §4.3.

## 2026-05-21 — DuckDB как локальный store (не Postgres)

**Контекст.** Нужно persistent-хранилище для редактируемых регламентов.
Заменить «хардкод в фикстурах» на реальный store.

**Решение.** DuckDB single-file + `threading.RLock()`. Три таблицы:
`regulations`, `parameters`, `regulation_history`.

**Альтернативы:**
- SQLite — отвергнуто: меньше типов для JSON-snapshot
- Postgres — отвергнуто: overhead для single-user prototype
- In-memory — отвергнуто: persistance важна

См. skills.md «DuckDB как локальный store».
