# Урок: «✓ 0/0 — это не пройдено»

> Контекст: у РАГРАФ есть прогонщик приёмки `scripts/acceptance_tests.py`,
> перенесённый из платформы АРХИ. Он запускает pytest, разбирает строки
> PASSED / FAILED / SKIPPED и печатает таблицу «пункт задания — описание —
> итог» по файлам проверок.

## Что произошло

Итоговая строка таблицы считается так:

```python
n = st["ok"] + st["bad"]
mark = "✓" if st["bad"] == 0 else "✗"
rows.append((mark, tz, what, f"{st['ok']}/{n}"))
```

(`scripts/acceptance_tests.py:1198–1200`). Пропуски копятся в `slot["skip"]`
(`:573`), но ни в таблицу, ни в итог не попадают. Файл с пятью проверками,
из которых две пропущены, показан как «✓ 3/3»; файл, где пропущены все, —
как «✓ 0/0».

## Почему это случилось

- **Два исхода вместо четырёх.** Прогонщик пришёл из АРХИ с исходами «прошло»
  и «упало»; пропуску места не нашлось, и он выпал из счёта.
- **Ключ — файл, а не требование.** Один файл закрывает несколько пунктов
  задания, и «зелёный файл» читается как «закрыты все его пункты».
- **pytest сам считает пропуск успехом:** код возврата 0, если ничего не упало.
  Прогонщик унаследовал это значение молча.

## Как починили

Пока не починено. Работа П-1 ПМИ РАГРАФ-ФРЕЙМ-51 (07.11.2026): параметр изделия,
таблица по номерам испытаний и пунктам ТЗ, четыре исхода (ПРОЙДЕНО, ЧАСТИЧНО,
НЕ ПРОЙДЕНО, ПОКАЗОМ); пропуск — непройдено; прогон — пакетом `polnyy`.

## Чтобы не повторилось

- **У прогонщика приёмки пропуск — не успех.** Пропуск печатается отдельной
  колонкой и делает исход испытания «НЕ ПРОЙДЕНО». Исключение — объявленный
  пропуск («проверке нужна внешняя система»), но тогда исход — «ПОКАЗОМ»
  со сценарием, а не «ПРОЙДЕНО».
- **Ключ — пункт задания.** Файл — средство, а не единица приёмки: итог считается
  по испытаниям, каждое из которых называет свои проверки.
- **«0 из 0» — красный.** Испытание, у которого не выполнилось ни одной проверки,
  не пройдено.
- **Сторож самого прогонщика:** подставной файл с одной пропущенной проверкой →
  в протоколе НЕ ПРОЙДЕНО. Увидеть его красным на нынешнем прогонщике.
- **Переносится на любой стек:** `test.skip` в Jest, `@Disabled` в JUnit,
  `t.Skip` в Go — по умолчанию пропуск прогон не роняет нигде.

## Чем обнаружено

Чтением исходного текста прогонщика при составлении ПМИ (07.11.2026): требовалось
понять, можно ли выдать протокол фреймворка этим прогонщиком. Набор проверок
этого показать не мог: пропуск в нём зелёный по определению.
