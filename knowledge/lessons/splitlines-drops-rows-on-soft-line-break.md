# Урок: `splitlines()` рвёт строку таблицы на мягком переносе

## Что произошло

В LEYKA заводили контрольные точки «Общего плана деятельности» задачами.
Скрипт читал Markdown-таблицу плана (`docs/Общий План Деятельности 06102026.md`,
53 пункта), брал из неё дословные тексты и сроки и создавал по задаче на пункт.
Сухой прогон остановился:

```
План и SPEC расходятся по пунктам: ['85', '89', '98.1']
```

По мнению разбора, этих трёх пунктов в таблице не было. В редакторе их строки
выглядели целыми. Странность была одна: склейка без пробела —
«…на третью версию фреймворка.Разработка положения…».

## Почему это случилось

В трёх ячейках между двумя предложениями стоит невидимый символ U+000B
(вертикальная табуляция):

```
п. 85    …на третью версию фреймворка.⟨0x0B⟩Разработка положения…
п. 89    …(для подсистемы «ВОЗДУХ-ОМ»).⟨0x0B⟩Эксплуатационная документация…
п. 98.1  …формирования графика работы.⟨0x0B⟩Инструктаж (обучение)…
```

Офисные форматы так кодируют мягкий перенос (Shift+Enter) — новую строку
внутри того же абзаца. Word отдаёт его символом 11, python-pptx — тоже как `\v`.
Файл, судя по разметке (`\-`, `1\.`, `| :---: |`), выгружен из Google Docs
в Markdown, и перенос внутри ячейки доехал как есть. В документации Google
я подтверждения не нашёл: это вывод из того, где именно стоит символ.

`str.splitlines()` режет не только по `\n`, а по целому списку разделителей:
`\r`, `\x0b`, `\x0c`, `\x1c`–`\x1e`, `\x85`, ` `, ` `. Строка таблицы
распалась на две половины. Ни в одной не набралось восьми ячеек, и разбор,
отбрасывающий строки «не той формы», выкинул обе без ошибки.

Проба на невидимые разделители:

```sh
python3 -c "import sys; t = open(sys.argv[1], encoding='utf-8').read(); \
print({hex(ord(c)): t.count(c) for c in set(t) if c in '\r\x0b\x0c\x1c\x1d\x1e\x85  '})" \
  "docs/Общий План Деятельности 06102026.md"
# {'0xb': 3}
```

## Как починили

Строки читаются только по `\n`, а внутри ячейки `\x0b` превращается в обычный перенос:

```python
for line in path.read_text(encoding="utf-8").split("\n"):   # было: .splitlines()
    ...
text = text.replace("\x0b", "\n")                          # в очистке ячейки
```

После правки разобрались все 53 пункта. Задачи п. 85 (Каппа), п. 89
(Экомониторинг) и п. 98.1 (Локобригады, срок 01.11) заведены.

## Чтобы не повторилось

- **Выгрузки читать через `split("\n")`, а не через `splitlines()`.**
  `splitlines()` годится для текста, который ты написал сам. В выгрузках
  из Word, Google Docs и PowerPoint внутри «строки» живут `\v`, `\f`, ` `.
- **Перед разбором прогнать пробу на невидимые разделители** (команда выше).
  Если она что-то нашла, открыть эти места, а не гадать.
- **Разбор сверяется с независимым списком и при расхождении падает, а не
  предупреждает.** Здесь спасло именно это: разобранные пункты сравнивались
  с пунктами, для которых названия написаны вручную, и скрипт остановился
  до записи. Без сверки три КТ из 53 молча не попали бы на доску. Одну
  из них (98.1, срок через три недели) заметили бы только по сорванному сроку.
- **«Строка не той формы — пропустить» — опасное умолчание.** Если пропуск
  допустим, его надо считать и показывать: «разобрано 50, пропущено 3: …».
