# Mapping: Product Focus ↔ 9 стадий ЖЦ vault'а

Этот плейбук — **мостик** между общей методологией Product Focus
(см. [concepts/product-focus](../../concepts/product-focus.md)) и моей
локальной 9-стадийной картой ЖЦ (см. [00-product-lifecycle](00-product-lifecycle.md)).

> **Зачем мостик:** Product Focus описывает **общие** инструменты
> продакт-менеджмента. Моя 9-стадийная карта — **российская специфика**
> (ТЗ ГОСТ-19, КОСГУ-устав, НИР). Их надо соотнести: на какой моей
> стадии какие инструменты PF применять.

---

## Mapping 6 стадий PF ↔ 9 стадий vault'а

```
Product Focus           Vault (9 стадий)            Главный артефакт
─────────────           ──────────────────          ─────────────────
1. Discovery     ───►   1. Idea formalization       IDEA.md
                  ───►   2. Niche / positioning      STRATEGY-POSITIONING.md
                  ───►   3. ТЭО / НИР                ECONOMICS-MARKETING.md
                                                    
2. Development   ───►   4. Tech spec (ГОСТ 19.201)   TZ_<X>_GOST19.md
                  ───►   5. Architecture             ARC.md (18 секций)
                  ───►   6. SKILL-NN series          SKILL-01 … SKILL-NN
                                                    
3. Piloting      ───►   7. ГОСТ-19 doc set           UserManual + PMI + …
                                                    
4. Deployment    ───►   8. README + landing          README.md / README-en.md
                                                    
5. Scaling       ─┐
                  ├──►  9. Charter / report / growth Charter + IQ-roadmap
6. Leading       ─┘
```

**Главное наблюдение:** Discovery в PF = 3 стадии в моей карте (1+2+3).
Это потому что для **российского коммерческого** контекста нужно
проработать ниши и ТЭО отдельно (грантовая отчётность, защита бюджета),
а в общей PF-схеме они слиты.

## Какие инструменты PF использовать на каждой моей стадии

### Стадия 1 — IDEA (Idea formalization)

| 4 фокуса PF | Что вытаскиваем в IDEA.md |
|-------------|---------------------------|
| **Клиент** | §1 «Кто пользователь?» — JTBD-формулировка job |
| **Продукт** | §2 «Какую задачу решаем?» |
| **Бизнес** | §6 «Бюджет ресурсов» (тут только мини-версия) |
| **Тренды** | (в IDEA необязательно, потом в стадии 2) |

**Инструменты:** [JTBD](../../concepts/jtbd.md) — главный. Карта
стейкхолдеров (опционально, из Дизайн-мышления).

**Метод:** проблемное интервью ИЛИ глубинное ИЛИ JTBD-интервью —
**выбрать один** (см. правило конкуренции из PF).

### Стадия 2 — Niche / Positioning

| 4 фокуса PF | Что в STRATEGY-POSITIONING.md |
|-------------|-------------------------------|
| **Клиент** | §3-4 — 3 устойчивые ниши, JTBD-сегментация |
| **Продукт** | §1 — формула позиционирования, что отличает |
| **Бизнес** | §3 — конкурентный ландшафт, TAM/SAM/SOM |
| **Тренды** | §1 — теоретическая рамка («академический ров») |

**Инструменты:** [Lean Canvas](../../concepts/lean-canvas.md) (на одну
страницу), Blue Ocean Strategy, Пропасть Мура, Трендвотчинг.

### Стадия 3 — ТЭО / НИР

| 4 фокуса PF | Что в ECONOMICS-MARKETING.md |
|-------------|------------------------------|
| **Бизнес** | TAM/SAM/SOM, юнит-экономика, TCO/ROI по сегментам |
| **Клиент** | Категории пользователей (3-5 ролей) с экономикой |
| **Продукт** | (минимально, MVP-валидация уже в стадиях 4-6) |
| **Тренды** | 5-летняя траектория с драйверами |

**Инструменты:** Юнит-экономика, AARRR, Воронка пилотирования (не SaaS).

### Стадия 4 — ТЗ

**В PF это уже Development**, но в моей карте — отдельная фаза. На
этой стадии **выбираешь инструменты из PF**:

| Слой пирамиды PF | Что у нас |
|------------------|-----------|
| Ценности | (фиксируются неявно через ТЗ §1.2 — методологическая основа) |
| Модели | Задачный подход / ТФС Анохина / Sigma — указать в ТЗ |
| Методы | (выбираются ниже, в стадии 5-6) |
| Инструменты | (выбираются на стадии 6) |

### Стадия 5 — Архитектура (ARC.md)

PF не покрывает архитектурный документ — это специфика технического
исполнения. Но Pyramid (Модели → Методы → Инструменты) хорошо
маппится на разделы ARC.md:

| Раздел ARC.md | Слой PF |
|---------------|---------|
| §1-3 Обзор + слоистая + author/model/execute | Модели |
| §4-9 Доменная модель, ЖЦ, DSL, ETL, store, versioning | Методы |
| §10-12 Хранилище + API + деплой | Инструменты |
| §15 ADR | (Ценности на проектном уровне) |

### Стадия 6 — SKILL-NN серия

В PF это «Прикладные фреймворки, методы, практики» (Регламенты и
Инструкции). Каждый SKILL-файл = один method.

**Mapping типичных SKILL'ов на 4 фокуса:**

| SKILL-NN тематика | Какой фокус усиливает |
|-------------------|----------------------|
| SKILL-01-idea | Клиент + Продукт |
| SKILL-02-setup, SKILL-INFRA, SKILL-AUTH | Продукт (технический слой) |
| SKILL-AI-PLAYBOOK | Продукт + Тренды |
| SKILL-DevSecOps, SKILL-RELEASE | Продукт (надёжность) |
| SKILL-KANBAN, SKILL-WIKI | Команда (фокус управления) |
| SKILL-PROJECT-CHARTER-AND-REPORTS | Бизнес + Команда |
| SKILL-09-demo-mode | Бизнес (sale-ready) |

### Стадия 7 — ГОСТ-19 doc set = Piloting

Здесь PF и моя карта расходятся. PF на этапе Piloting подтверждает
ценность и продажи. Моя карта говорит — оформи 4-5 ГОСТ-19 документов.

**Совместить:** ГОСТ-19 документы нужны для **формального** пилота
(гос/корп), а PF-инструменты Piloting (пилот «один регламент за 2-3
недели», метрики до/после) — для **сути** пилота.

### Стадия 8 — README + лендинг = Deployment

| 4 фокуса PF | Куда попадает в README |
|-------------|------------------------|
| Клиент | §«Зачем X» — value prop |
| Продукт | §«Главные фичи», главный сценарий |
| Бизнес | §«Коммерческая ценность» (для категории A/C) |
| Тренды | Введение в Mermaid-схеме контекста рынка |

### Стадия 9 — Charter / report / growth = Scaling + Leading

**Здесь применяется 3-я модель PF — фокусы управления (Ритм / Команда /
Интеграция).**

| Фокус управления PF | Артефакт в моей карте |
|---------------------|----------------------|
| **Ритм** | OKR в Charter §7, IQ-roadmap, HADI-цикл (если есть рост-hypothesis) |
| **Команда** | Charter §4 (исполнители + FTE), [people/](../../people/) |
| **Интеграция** | Charter §11 (лист согласования), оргструктура НГУ/ЦИИ |

## Когда применять Product Focus поверх моих 9 стадий — а когда нет

| Категория проекта (ADR-002) | Применять PF? |
|-----------------------------|---------------|
| **A — заказной коммерческий** | ✅ Полностью. PF + 9 стадий = полная картина. |
| **B — pet** | ⚠ Только Discovery (стадия 1) + минимальный Lean Canvas. Тяжёлая PF — overkill. |
| **C — научно-инструментальный** | ✅ Особенно фокус «Тренды» и «Бизнес» (через STRATEGY-POSITIONING). Команда/интеграция облегчённо. |
| **D — демо** | ⚠ Только стадии 1+2 (Idea + позиционирование). Дальше — техническое демо. |

## Ключевые принципы из Product Focus, которые усиливают мою методологию

1. **Можно стартовать с любого фокуса**, не обязательно с «Клиента».
   Был пример Apple iPod — стартовали с Технологии. Это разрешение
   входить в [discovery-interview](../../knowledge/skills/discovery-interview.md) с любой стороны.

2. **Модели конкурируют, инструменты можно смешивать.** Если выбрал
   JTBD — основные интервью JTBD, но карта стейкхолдеров из
   Дизайн-мышления и «Спросите маму» как универсальные правила — добавь.

3. **Фокусы управления — отдельный слой.** Agile/OKR — не про создание
   продукта, а про управление командой. Это объясняет, почему
   [knowledge/skills/](../../knowledge/skills/) у меня содержит
   process-skills отдельно от product-skills.

4. **Стадии — это маршрут, не ритуал.** Каждая стадия имеет свои
   этапы и инструменты, но **можно идти ускоренным маршрутом** (3-week
   fast track) или **полным** (8-week). Зависит от категории и
   ограничений.
