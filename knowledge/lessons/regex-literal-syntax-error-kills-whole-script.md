# Урок: «одна скобка в регулярке выключила весь калькулятор»

> Контекст: проверка ИИ-ассистента GigaCode (`~/ENGINEER`). Запрос из трёх фраз —
> инженерный калькулятор в браузере; результат — `index.html`, `style.css`, `script.js`
> без сборки, функции вызываются из `onclick` в разметке.

## Что произошло

Страница открывается, интерфейс аккуратный, но на нажатия ничего не меняется:
табло показывает «0». Ни сообщений, ни подсказок — без консоли браузера не видно ничего.

Агент, написавший код, искал причину 17 шагов: перечитывал файлы, поднимал серверы,
проверял `curl`, что `script.js` отдаётся и что в нём есть строка `function insertChar`.
Основная версия — «браузер блокирует скрипты при открытии через `file://`» (34 упоминания),
затем по подсказке пользователя — «не запущен бэкенд». Ошибку так и не нашёл.

## Почему это случилось

В `script.js:132`:

```javascript
const funcMatch = expression.match(/([\w]+\($/);   // группа ( не закрыта
```

**Литерал регулярного выражения проверяется при разборе файла, а не при выполнении
строки.** Неправильный литерал — ранняя синтаксическая ошибка: браузер не выполняет
ни одной строки файла. Отсюда картина «нарисовано, но мёртво»:

* HTML и CSS — отдельные файлы, они отрисованы полностью;
* в `script.js` не объявлена ни одна функция, каждое `onclick` падает
  с `ReferenceError: insertChar is not defined`;
* табло показывает текст из разметки — `0`.

Ошибка выполнения выключила бы одну функцию. Синтаксическая — весь файл, поэтому
симптом выглядит как «скрипт не подключён», и диагноз уходит к серверу и путям.

Строкой выше агент написал почти такое же выражение правильно: `/([\d.]+|[\w]+\()$/`.
Это ошибка копирования с искажением, а не незнание синтаксиса — такие ловит только
механическая проверка, глазами их пропускают и человек, и модель.

**Версия про `file://` для этого случая ложна.** Классический `<script src="…">`
по `file://` загружается и выполняется. Ограничения `file://` касаются `fetch`/XHR
и модулей `<script type="module">`, но не обычных скриптов.

## Как починили

Закрыли скобку: `/([\w]+\()$/`. Одна эта правка подняла пользовательские сценарии
с 2 до 19 из 48. Дальше счёт переписан без `eval` и регулярных подстановок, и все
48 сценариев проходят. Подробно — `~/ENGINEER/docs/KALKULYATOR-RAZBOR.md`, разрыв Р1.

## Чтобы не повторилось

**Признак → первое действие.** «Страница нарисована, а ни одна кнопка не реагирует» —
значит, скрипт не выполнился. Первое действие — **консоль браузера** (Cmd+Opt+J
в Chrome, Cmd+Opt+C в Safari): там будет `SyntaxError` с номером строки. Сервер,
пути и CORS — только после консоли.

**Дешёвые ворота для каждого `.js`, который подключается обычным `<script>`:**

```bash
node --check script.js                 # SyntaxError ... (строка 132)
osascript -l JavaScript script.js      # на любом Mac без Node:
                                       # «Error on line 132: SyntaxError: ... missing )»
```

`osascript` выполняет файл после разбора. Браузерный скрипт упадёт на первом обращении
к `document`, и это нормально: синтаксическая ошибка выглядит иначе — `SyntaxError`
с номером строки до всякого выполнения. Для скриптов с побочными действиями этот
способ не годится — только `node --check`.

**Проверка поведения, а не наличия.** Что файл отдаётся сервером и в нём есть нужная
строка, доказывает только наличие текста. Доказательство работы — нажатие и результат:
страница-стенд, которая в рамке нажимает кнопки и сверяет табло, прогоняемая в
настоящем браузере (`~/ENGINEER/tests/scenarios.html`; без участия человека —
headless Chrome с `--dump-dom`).

**В задаче агенту:** «после записи каждого `.js` выполни `node --check` и покажи вывод».
