# Урок: переход к разделу гармошки уводит не туда

## Что произошло

Страницу администратора АРХИ пересобрали в гармошку: семь разделов `details`,
раскрыт не больше одного, сверху закреплённый перечень разделов. Владелец
нажимал «Рассылка» — страница прокручивалась так, что наверху оказывался
**предыдущий** раздел, «Журнал испытаний».

Жалоба звучала как одна поломка. Причин оказалось **три**, независимых,
и правка каждой не закрывала остальных.

## Почему это случилось

**1. Отступ под закреплённую шапку написан числом.** Стояло
`scroll-margin-top: 9rem` (144 px) при фактических 143 px — заголовок
вставал вплотную под полосу и читался прижатым. Угадать это число нельзя
в принципе: верх складывался из трёх полос, а перечень разделов переносится
на вторую строку в узком окне и меняет высоту верха вдвое.

**2. Сосед схлопывался ПОСЛЕ прокрутки.** Раскрытие цели ставило
`r.open = true`; соседа закрывал обработчик `toggle`, а событие это браузер
шлёт **отложенно**. Позиция считалась по раскладке, в которой сосед ещё
занимал место; страница укорачивалась уже после `scrollTo`, всё нижнее
уезжало вверх — и на месте, куда подвели, оказывался раздел выше цели.

**3. Странице не хватало длины.** Это следствие самой гармошки: пока раскрыты
были все разделы, документ был длинный. Когда раскрыт один, нижние разделы
стоят почти в конце документа, и браузер **обрезает прокрутку по его концу**.
Средство считало цель верно, а доехать было некуда.

Отдельно коварно: **на первом разделе промах не виден никогда.** Он стоит
выше линии прокрутки, прокручивать к нему нечего, и проба, поставленная
на нём, даёт ложное «в порядке». Владелец так и сказал: «на первый раздел
работает корректно».

## Как починили

```js
// 1. Высота закреплённого верха ЗАМЕРЯЕТСЯ и кладётся в свойство,
//    то же число берёт правило scroll-margin-top.
function otmeritVerh() {
  var v = Math.round(document.querySelector(".verhnyaya-oblast")
                             .getBoundingClientRect().height);
  document.documentElement.style.setProperty("--vysota-verha", v + "px");
  return v;
}

// 2. Раскрытие закрывает соседей САМО и сразу, до замера.
function razvernut(r) {
  razdely().forEach(function (d) { if (d !== r) { d.open = false; } });
  r.open = true;                       // getBoundingClientRect ниже
}                                       // принудит пересчёт раскладки

// 3. Недостающая длина добирается запасом внизу — ровно сколько нужно.
function podvesti(r) {
  var cel = Math.max(0, r.getBoundingClientRect().top + window.pageYOffset
                        - otmeritVerh() - 14);
  var bezZapasa = document.documentElement.scrollHeight - ZAPAS_VNIZU;
  postavitZapas(cel + window.innerHeight - bezZapasa);   // может быть 0
  window.scrollTo({ top: cel });
}
```

Запас держится **числом в переменной**, а не читается из разметки: высоту
документа надо знать без него, иначе он растёт от самого себя на каждом
переходе. Свёртка запас снимает — иначе он станет пустотой над подвалом.

## Чтобы не повторилось

- **Сделал гармошку (раскрыт один раздел) → проверь самый нижний раздел.**
  Именно он упирается в конец документа. Верхние работают всегда.
- **Отступ под закреплённую шапку не пишется числом.** Замерять и класть
  в CSS-переменную; в правиле оставить только запасное значение с избытком.
- **Всё, что меняет длину документа, делается ДО замера позиции.** Событие
  `toggle` у `details` отложенное; на него полагаться нельзя. Нативная
  «эксклюзивная гармошка» (`<details name="...">`) закрывает соседей
  синхронно, но поддержана не везде — запас на сценарии нужен всё равно.
- **Проба раскладки ставится на нижний край, а не на первый экран.** Класс
  дефектов «положение на экране» набор проверок не ловит по устройству:
  всё зелено, данные верны, а человек видит не то.
