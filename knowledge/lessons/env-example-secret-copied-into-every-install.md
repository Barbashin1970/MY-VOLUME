# Урок: «образец, который копируется в настройки, — это настройки по умолчанию»

> Контекст: РАГРАФ — локально устанавливаемое изделие (сервер на 127.0.0.1).
> Изменяющие действия закрывает один общий пароль `ADMIN_PASS`; пустой пароль —
> защита выключена. Лаунчеры `start.command` и `start.bat` при первом запуске
> копируют `backend/.env.example` в `backend/.env`.

## Что произошло

- 22.05.2026 в образец положили учебный пароль — «чтобы ученик сразу попробовал
  защищённые действия». С тех пор у каждой установки лаунчером был один и тот же
  пароль, известный всем, у кого есть репозиторий.
- Значение жило не в одной строке: его повторяли комментарий над `ADMIN_PASS=`
  («Дефолт ниже (…)») и примечание в описании программы. Маска строки `ADMIN_PASS=`
  при разборе пропустила комментарий, и значение попало в вывод.
- Установщик Windows образец в `.env` не копирует — установки им работали без
  пароля. Поведение изделия зависело от пути установки.
- Набор проверок молчал: в нём `ADMIN_PASS=""` выставлен окружением, а окружение
  важнее файла.

## Почему это случилось

- **Образец путали с подсказкой.** «Образец» задумывался как перечень ключей,
  но лаунчер, копирующий его в `.env`, превращает каждое значение образца
  в действующую настройку.
- **Пароль в файле на том же диске не защищает от пользователей этого диска.**
  Любой пользователь компьютера откроет `.env` и прочтёт пароль. Пароль имеет
  смысл там, где к службе обращаются по сети, — а локальная служба слушает
  только 127.0.0.1.

## Как починили (08.11.2026, решение владельца)

- В образце — `# ADMIN_PASS=`, блок того же размера: номера строк, на которые
  ссылаются документы, не сдвинулись. Значение убрано и из комментария,
  и из описания программы; поиск по репозиторию его больше не находит.
- Пустой пароль — открытый режим: `GET /api/auth/admin/check` отвечает
  `enabled=false`, и пункт «Админ» в карточке ролей открывается щелчком.
  Проверено запуском с чистого каталога, где `.env` — копия образца.
- В лаунчерах — комментарий у копирования: настройки читаются только из `.env`,
  образец копируется один раз; компьютер общий — впишите свой пароль.
- Сторож `backend/tests/test_obrazec_nastroek.py` (видели красным на прежнем образце):
  - секреты — по классу настроек (поля с `repr=False`) и по имени ключа
    (`PASS`, `TOKEN`, `SECRET`, `API_KEY`);
  - копия образца при снятой переменной окружения даёт открытый режим;
  - заданный пароль требует входа: без cookie — 401;
  - сообщения называют только имена ключей.
- На установках, где `.env` создан до правки, прежний пароль остался: правка
  образца их не трогает, это сказано в руководстве системного программиста.

## Чтобы не повторилось

- **Образец, который копируется в настройки, проверяют как поставляемые
  настройки.** Секретов в нём нет — и это держит сторож, а не память.
- **Секрет — то, что код объявил секретом.** Перечень ключей для сторожа
  выводится из класса настроек (скрытые из представлений поля), а не пишется
  руками; плюс правило по имени — для ключей, которые читают вспомогательные
  сценарии мимо класса.
- **Проверка образца снимает переменную окружения.** Если набор проверок
  сбрасывает секрет окружением, проверка по настройкам службы пройдёт при любом
  образце: настройки строят из копии образца.
- **Сторож не печатает значения.** В сообщении — только имена ключей; текст файла
  не держат в кадре проверки: при `--showlocals` он уйдёт в журнал прогона.
- **Значение ищут по всему репозиторию — именами файлов, а не строк.**
  `grep -rlF -- "$znachenie" .` — значение повторяется в комментариях
  и документах, а маска одной строки его пропускает.
- **«Защиты паролем нет» на локальном изделии — решение, его записывают.**
  В документах — почему (файл открыт пользователям компьютера, служба только
  на 127.0.0.1) и как включить защиту, если компьютер общий.
- **Путь установки не меняет поведения.** Если один путь копирует образец,
  а другой нет, поведение двух путей сверяют проверкой.

## Чем обнаружено

Набор проверок секрета не видел по устройству.
