# Урок: «факт» из того же источника, что и прогноз

> Контекст: СИМА, пилот «снегопад по районам на 1–3 суток»
> (`docs/SNEGOPAD-RAZBOR.md`, фаза С.1). Скрипт `scripts/snow_retro/snow_retro.py`
> сравнивает прошлые прогнозы Open-Meteo (Previous Runs API, сутки 1–3) с фактом
> по точке центра города.

## Что случилось

В первой версии скрипта факт брался из Historical Weather API
(`archive-api.open-meteo.com/v1/archive`, `daily=snowfall_sum`) без параметра `models`.
Расчёт выдал правдоподобные числа: прогноз «снег от 2 см» на завтра назвал 77 %
снегопадов и сбылся в 88 %.

Второй раздел протокола сравнивал прогноз со «свежим прогнозом на тот же день» и дал
**те же числа до знака**. Сверка столбцов показала: суточный снег по «факту» и по свежему
прогнозу совпал на 1 047 сутках из 1 047.

## Почему

- **Модель архива по умолчанию — не ERA5.** `best_match` Historical Weather API для этих лет
  отдаёт ECMWF IFS высокого разрешения. Та же точка сетки (55,079; 82,994) и те же значения,
  что у Previous Runs API в сутки 0.
- **Название API обмануло.** «Historical Weather» читается как «реанализ», а на деле это
  лучшая доступная модель за прошлые даты. Реанализ — только с явным `models=era5`
  (точка сетки 55,0; 83,0, шаг 0,25°).
- **Правдоподобные метрики не проверяют постановку.** Прогноз за сутки до дня и свежий
  прогноз той же модели расходятся достаточно, чтобы числа выглядели как настоящая проверка.

## Как починили

`NSK_OpenData_Bot`, коммит `6bc1cf3`:
- факт запрашивается с `models=era5`, и это написано в докстроке скрипта и в протоколе;
- суточная таблица сохраняется в CSV: пересчёт и сверки идут без сети;
- после правки совпадений 780 из 1 047, почти все — сутки без снега. Числа стали другими:
  на 1 сутки названо 78 % и сбылось 78 %, на 3 суток — 65 % и 74 %;
- в разборе названо ограничение: ERA5 — реанализ 0,25°, а не замер на станции, и проверка
  идёт по одной точке города.

## Чтобы не повторилось

- **Источник факта — явно.** Модель, сетку и точку указывать в запросе и в протоколе.
  Не брать «по умолчанию» там, где по умолчанию можно получить тот же продукт, что проверяется.
- **Независимость — до метрик.** Посчитать долю точных совпадений прогноза и факта. Если
  она около 100 %, на ненулевых днях это один и тот же ряд.
- **Второй факт как сторож.** Сравнение с другим источником (свежий прогноз, станция, METAR)
  в том же протоколе: одинаковые числа по разным «фактам» — тревога.
- **Сырые данные — в файл.** Сверки делаются по сохранённой таблице, а не по памяти о запросе.
